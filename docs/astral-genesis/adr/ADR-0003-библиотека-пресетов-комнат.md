# ADR-0003: Библиотека пресетов комнат и подбор

**Статус:** Предложено
**Дата:** 2026-07-13
**Ответственные:** Янислав (арх./код)
**Связано:** ADR-0001 (двери ↔ рёбра графа) — этот ADR реализует его контракт «пресет объявляет слоты; подбор требует slots ≥ connections».

## Контекст

Генератор ([rs_level_graph.gd](../../../src/resources/world_generator/rs_level_graph.gd))
строит граф, но каждому узлу проставляет один и тот же `PLACEHOLDER_ROOM_SCENE`
(`test_room.tscn`, 1 дверь). У узлов при этом обычно 2–5 рёбер → `RunManager`
привязывает только `connections[0]`, остальное роняет с warning'ом, и бóльшая
часть забега недостижима. `RS_RoomPresetLibrary` был пустой заглушкой.

Нужен селектор, который на узел подбирает реальную сцену комнаты так, чтобы:
1. дверных слотов хватало на все рёбра узла (жёсткий контракт из ADR-0001);
2. комната подходила по роли (`vertical_hub`, `level_exit` …);
3. выбор был разнообразным, но детерминированным по сиду.

## Решение

Два ресурса + селектор.

**`RS_RoomPreset`** — один вариант комнаты (данные): `scene: PackedScene`,
`tags: Array[StringName]` (что комната умеет), `slot_count: int` (сколько в ней
`C_DoorSlot`), `weight: float`.

**`RS_RoomPresetLibrary`** — `presets[]` + `fallback` + `select_preset(node, rng)`:

1. **Вместимость** (жёстко): `preset.slot_count >= node.connections.size()`.
2. **Теги** (жёстко): `node.tags ⊆ preset.tags`. Узел без тегов подходит любому
   пресету по этому критерию; узел с `{vertical_hub}` — только пресетам, которые
   `vertical_hub` предоставляют.
3. **Специфичность** (мягко): среди кандидатов оставляем те, у кого **меньше всего
   лишних тегов** сверх требуемых узлом, затем — взвешенный рандом по `weight`.
4. **Fallback**: нет кандидатов → `fallback` (или null → генератор оставляет placeholder).

Подстановка идёт **одним финальным проходом** `_assign_room_scenes(rng, library)`
в конце `generate_run`, когда все `connections` уже проставлены — раньше нельзя,
т.к. до этого неизвестно нужное число слотов. Библиотека протаскивается параметром
`generate_run(seed, library)` (Resource не тянет автозагрузки); `RunManager` берёт
её из `GameConfig.config.room_preset_library`. `library == null` → всё как раньше
(placeholder), поэтому изменение обратно совместимо до появления данных.

### Почему «специфичность», а не просто теги-подмножество

Критерий №2 в одну сторону (`node ⊆ preset`) пропустил бы «богатый» пресет в
бедный узел: комната-с-порталом (`{vertical_hub}`) формально годится обычному
узлу (которому нужно `{}`). Критерий №3 это чинит декларативно: обычный узел
получит пресет с 0 лишних тегов (простую комнату) в приоритете над `vertical_hub`.
Так порталы/лифты не протекают туда, где они не нужны, без ручных чёрных списков.

## Рассмотренные варианты

| Вариант | Подбор | Вердикт |
|---|---|---|
| A. Жёсткая карта `тег → сцена` | по одному тегу-роли | нет разнообразия, нет учёта числа слотов; отклонено |
| B. Теги-подмножество + специфичность + вес (выбрано) | множество тегов, декларативно | разнообразие + нет протечек + детерминизм |
| C. Полноценные правила/веса per-depth, констрейнт-солвер | выразительно | избыточно до появления контента; отложено |

## Последствия

- **Проще:** дверная траверсия становится проходимой, как только появятся
  многодверные комнаты; генератор больше не лепит один placeholder на всё.
- **Сложнее:** теперь есть контракт «`slot_count` пресета = число `C_DoorSlot` в
  сцене». Рассинхрон ловит `RS_RoomPresetLibrary.validate()` (инстанцирует и
  считает) — звать из теста/дебага.
- **Осторожно:** пока не заавторены комнаты с 2+ слотами, узлы с многими рёбрами
  падают в `fallback` (placeholder) — деградация плавная, но граф всё ещё
  частично недостижим, пока нет контента.
- **Пересмотреть позже:** слоты сейчас безымянно-считаемые; типы связей
  (лифт/лестница/коридор) не влияют на вид прохода. Когда понадобится «лифт ≠
  дверь», ввести *kind* у `C_DoorSlot` и матчить по типу `RS_LevelConnection`
  (см. ADR-0001, отложенное умное сопоставление слот↔ребро).

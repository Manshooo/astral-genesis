# ADR-0002: Захват тела и модель воплощения

**Статус:** Предложено
**Дата:** 2026-07-13
**Ответственные:** Янислав (арх./код)

## Контекст

«Захват тела» — заявленная основная атака и стержень всех перков (см.
`docs/astral-genesis/История.md`). Игрок — БФЖ, бестелесное сознание: сбежало из
сосуда, вне тела **распадается** (запас жизни тикает), должно вселяться в тела,
перки улучшают/модифицируют захваченное тело, финальный перк — действовать без тела.

Механики **нет**: `C_BodySnatch { capture_range, capture_success_chance }` и
`C_Lifespan { max_duration, current }` существуют, `S_ApplySkillEffects` их тюнит,
но нет системы, которая захватывает тело, и нет системы, которая тикает распад.
`S_ApplySkillEffects` вообще работает вхолостую: запрос
`with_all([C_Lifespan, C_BodySnatch])` не матчит ничего — эти компоненты не висят
ни на одной рантайм-сущности (в `e_player.tscn` их нет).

### Жёсткое ограничение архитектуры

Всё управление завязано на **единственную `E_Player`**: `S_PlayerInput`,
`S_FPSLook`, `S_PlayerMovement`, `S_InteractionDetector` кастуют сущность
`as E_Player` и читают `.camera` / `.interact_ray` / `is_on_floor()`. Враг —
другая сцена без этого интерфейса. Поэтому «стать врагом = перенести управление
на его сущность» невозможно без рефактора трёх систем.

### Требования

1. Захват: навёлся на тело, ЛКМ, бросок на `capture_success_chance`, при успехе — вселение.
2. Два состояния БФЖ: **воплощён** (есть тело, здоровье тела) и **развоплощён**
   (призрак; тикает `C_Lifespan`; истечение = настоящая смерть, конец забега).
3. Смерть тела (HP → 0) выбрасывает БФЖ из тела в развоплощён, а не завершает забег.
4. Захват тела дозаправляет запас жизни (снимает давление распада).
5. Перки модифицируют характеристики захваченного тела — у «тела» должны быть данные.
6. Не ломать существующие системы управления (не трогать их запросы/касты).

## Решение

**«Душа-риг + состояние воплощения».** Постоянный управляемый объект — `E_Player`
(камера + ввод + коллайдер + луч). Это «текущая точка присутствия БФЖ», а не
конкретное тело. У него всегда есть компоненты-идентичность БФЖ:
`C_BodySnatch` + `C_Lifespan` (даём через `E_Player.define_components()` — чистый
код, без правки сцены; попутно чинит вхолостую работающий `S_ApplySkillEffects`).

**Состояния** (различаются наличием компонентов на `E_Player`):

| Состояние | Компоненты | Поведение |
|---|---|---|
| Воплощён | `C_Embodied` + `C_Health` | здоровье тела; распад на паузе; можно получать урон |
| Развоплощён | нет `C_Embodied`, нет `C_Health` | призрак; тикает `C_Lifespan`; урон не берётся, но идёт распад |

**Тело** — сущность (враг) с `C_BodySnatchable`, несущим характеристики, которые
тело даёт при вселении (пока `max_health`; сюда же лягут перк-модифицируемые
статы). Тела живут на слое `enemies` (layer_3).

**Захват** (`S_BodySnatch`): луч из камеры по маске `enemies` в пределах
`capture_range` → бросок `capture_success_chance` → при успехе **вселение**:
1. душа перенимает свежий `C_Health` из `C_BodySnatchable.max_health`;
2. вешается `C_Embodied`;
3. `C_Lifespan.current` дозаправляется до `max_duration`;
4. точка присутствия переносится в тело (риг → трансформ тела);
5. исходная сущность-тело **поглощается** (`remove_entity`);
6. событие `body_snatched`.

**Смерть тела → развоплощение** (`O_ExpelFromBody`, наблюдатель на `entity_died`
для сущности с `C_Embodied`): снять `C_Health` и `C_Embodied` → БФЖ снова призрак,
`C_Lifespan` возобновляет тик. **Истечение распада в развоплощён** (`S_Lifespan`) —
настоящая смерть: событие `run_ended`.

Ключевое: все системы управления остаются нетронутыми — они по-прежнему видят одну
`E_Player` с `C_PlayerInput`. Захват = обмен данных (статы/состояние) на одном
риге, а не переселение управления между сущностями.

## Рассмотренные варианты

### Вариант A: Перенос управления на сущность-тело
На захвате `C_PlayerInput`/`C_FPSCamera` и камера-риг переезжают на врага; враг
становится управляемым.

**Плюсы:** «по-настоящему» становишься телом как отдельной сущностью.
**Минусы:** системы управления кастуют `as E_Player` и лезут в `.camera`/
`.interact_ray`/`is_on_floor()` — враг этого не имеет. Требует, чтобы каждое тело
было `E_Player`-совместимым, либо рефактора трёх систем. Перенос нод камеры между
сущностями хрупок. Отклонено как несоразмерно дорогое.

### Вариант B: Душа-риг поглощает тело (выбрано)
Описан в «Решении».

**Плюсы:** ноль изменений в системах управления; естественно ложится на FP-игру
(ты и есть тело, в котором находишься); два состояния тривиально выражаются
наличием компонентов; чинит `S_ApplySkillEffects`.
**Минусы:** тело не симулируется как независимая сущность после захвата (оно
поглощено). Для FP-возможения это скорее фича, чем баг.

### Вариант C: Обобщить управление на любую `C_Controlled`-сущность
Ввести тег `C_Controlled`, убрать `as E_Player` из систем, камера следует за
управляемой сущностью через relationship.

**Плюсы:** чистый ECS; тела остаются самостоятельными сущностями.
**Минусы:** рефактор `S_FPSLook`/`S_PlayerMovement`/`S_InteractionDetector` +
переустройство камеры; большой объём до появления первого врага. Отложено:
вернуться, если телам понадобится независимая симуляция (напр. брошенное тело
продолжает жить).

## Анализ компромиссов

Стоимость сместилась в **связанность систем управления с `E_Player`**. A и C
платят за «тело = независимая сущность» рефактором этого узла; B принимает эту
связанность как данность и делает захват обменом данных на одном риге. Пока в игре
нет сценариев, где покинутое/захваченное тело должно жить своей жизнью, богатство
C не окупается. B даёт играбельное ядро минимальной ценой и не закрывает путь к C
позже (состояния уже выражены компонентами).

## Последствия

- **Проще:** захват реализуется без единого изменения в системах управления;
  `S_ApplySkillEffects` начинает работать (у `E_Player` появляются `C_BodySnatch`+`C_Lifespan`).
- **Проще:** «воплощён/развоплощён» — это наличие/отсутствие `C_Health`/`C_Embodied`,
  бесплатно фильтруется запросами (`S_Lifespan`: `with_all([C_Lifespan]).with_none([C_Embodied])`).
- **Сложнее:** развоплощённое движение (призрак) семантически отличается от ходьбы
  телом — потребуется отдельный режим (полёт/невесомость) позже.
- **Осторожно (порядок кадра):** `S_Health` в момент смерти вешает `C_Dead` через
  командный буфер (отложенно) и синхронно шлёт `entity_died`. Наблюдатель
  `O_ExpelFromBody`, снимающий `C_Dead`/`C_Health`, обязан делать это тоже отложенно
  (через `cmd`/`call_deferred`), иначе снятие выполнится ДО применения `C_Dead` из
  буфера и БФЖ залипнет мёртвым. Реализуется вместе с наблюдателем, не в этом срезе.
- **Пересмотреть позже:** скорость передвижения читается глобально из
  `SettingsManager.settings.move_speed`; чтобы тело влияло на скорость, нужен
  per-entity компонент скорости (сейчас `C_BodySnatchable` несёт только `max_health`).
- **Пересмотреть позже:** смена визуала (меш тела) при вселении — вне первого среза.

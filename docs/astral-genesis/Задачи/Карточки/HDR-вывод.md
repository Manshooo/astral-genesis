# HDR-вывод

Целевая версия: не назначена. Заведена 20.10 по аудиту настроек проекта: флаги
HDR были включены 19.10, но с нынешним конвейером не работали и сняты —
[[Конвенции проекта]] → «Чего в `project.godot` нет намеренно».

Источник — страница Godot «HDR output» (4.7). HDR-**вывод** — не внутренний HDR
рендера (он есть всегда), а подача значений ярче 1.0 на HDR-экран, модель EDR:
предел — `Window.get_output_max_linear_value()`, в SDR он ровно 1.0.

## Что нужно, чтобы включить

1. **Окружения без SDR-только приёмов**: тонмаппер не Filmic и не ACES
   (`assets/world_environment.tres`, меню — Filmic), glow не Soft Light,
   **без `adjustment_color_correction`** — а на ней держится ползунок яркости
   (`LevelEnvironment.shadow_curve`). Яркость придётся перенести на другой
   механизм (подъём теней в своём постэффекте), иначе HDR её ломает.
2. **Тонмаппер Reinhard или AgX**: они масштабируют выход по
   `output_max_linear_value`; Filmic и ACES всегда дают SDR-диапазон.
3. **Драйвер**: Windows — `rendering/rendering_device/driver.windows = d3d12`
   (снят 19.10 в пользу Vulkan — решение пересмотреть), macOS — Metal,
   Linux — Wayland (GNOME ≥ 50). X11, Android и веб HDR-вывода не умеют.
4. `rendering/viewport/hdr_2d` и `use_hdr_2d` на SubViewport'ах (маска обводки,
   экраны меню), `display/window/hdr/request_hdr_output`.
5. **Интерфейс**: сверить вид меню и HUD после `hdr_2d` — смешивание 2D идёт в
   линейном пространстве. Блики интерфейса ярче белого — только через
   `output_max_linear_value` и коротко: экран целиком на пике слепит.
6. **Настройки игрока**: по образцу демо `misc/hdr_output` — переключатель HDR,
   опорный белый; калибровку яркости ([[Калибровка яркости]]) расширить
   схемой «чёрная точка / бумажный белый / пик».

## Риски

Целевое железо — UHD 630 ([[Конвенции проекта]]): d3d12 на нём не проверен.
Перенос яркости с color correction — отдельная работа с проверкой
`dev/settings_menu_check` (уровни окружения).

# Расстановка пропов в комнатах

Целевая версия: не назначена. Заведена 16.10: «обустройство комнат пропами» из
списка пользователя, затем уточнение — **зоны это биомы, комнаты подбираются по
правилам зоны, а внутри комнат процедурно расставляются структуры** (столы,
стулья, интерактивные объекты и прочее). Зоны — [[Типы комнат]], «Решения 16.10».
Ниже — что есть, что нашёл исследованием и что предлагается.

## Что есть сейчас

- Пропы и враги расставлены **руками в сценах комнат**; процедурной расстановки
  нет ([[Типы комнат]]: «населённости нет»). Исключение — маркеры, которые
  стример бросает по своему ГСЧ: враги `EnemySpawn*` (`RS_EnemyRoster.roll`),
  находки `EssenceSpot*`, тайники в тупиках.
- **Контракт пропа** ([[Метрики и кит]] §5, §3): origin, лицо смотрит в Godot +Z,
  габарит основания кратен 0.25 м; **пропы не заходят в зону перед сокетом** и
  не выходят за footprint коробки — это уже держит `room_shell_check`.
- Комнаты в игре собираются по маске (коробка 2×2×1 стиля P или X) — внутренность
  у них задаёт сцена (`default_room`, `lab_room`, `vivarium_room`…).
- Правило проекта: **что наполняет комнату, бросается из своего
  `hash([run_seed, depth, node_id, marker])`**, не из общего ГСЧ графа
  ([[Цикл забега]]).

## Исследование 16.10

Что нашлось по теме. Оговорка: часть источников — препринты и студенческие
работы, поиск по Brogue ничего не дал (конкретику про его «машинные комнаты»
я не проверил), а страницы с лекциями Caves of Qud на GDC Vault закрыты —
пользовался вики модинга.

**Слои подбора: от грубого к тонкому (Caves of Qud).** Зона строится
**цепочкой билдеров**, которые применяются по очереди: ранние — крупная
геометрия и раскладка, поздние — отдельные комнаты, встречи и мелкие детали;
после них идут постбилдеры. Содержимое (существа, предметы) берётся из
**таблиц популяции** — именованные таблицы с весами и стилем выбора
(например, «взять каждого»: фермер, пёс, три–шесть свиней), которыми заселяют
область. Шаблон зоны и таблица — данные, а не код. Для нас это почти один в
один «зона → правила подбора → таблица наполнения», как просил пользователь. Источник:
[Modding: Zone Builders](https://wiki.cavesofqud.com/wiki/Modding:Zone_Builders).

**Регионы из зёрен (биомы).** Классика — разбить плоскость по зёрнам (Вороной),
каждому зерну приписать свойства и по ним определять биом, смягчив границу шумом;
в генераторах подземелий биомы также «конкурируют» за области по своим условиям.
Тип комнаты можно брать из свойств самой комнаты (число выходов: чулан — один,
проходная — два, хаб — три и более) вместе с весами региона. Готового источника
«Вороной + типы комнат» я не нашёл — комбинировать надо самим. Это совпадает с
идеей зёрен зон из [[Типы комнат]].

**Расстановка мебели — решатель правил.** Самая применимая схема —
«rule-based solver» (Tutenel и др.): каждый объект подгоняется под правила про
себя и про уже стоящие; у объекта свободная зона (clearance), границы расстояния
до родителя (стул — к столу), направление лица и приоритет; объекты ставятся по
приоритету, при коллизии случайный повтор, при неудаче объект отбрасывается.
Вариант студенческой работы — те же поля плюс прямоугольные комнаты ради простых
пересечений. Другая линия — жадная оптимизация стоимости (Kán и Kaufmann, 2018):
крупная мебель оптимизатором по правилам, мелкие предметы — локальной процедурой.
Ещё одна — выученная статистика сочетаний предметов (Henderson и др., 2017)
с отбраковкой нарушающих ограничения образцов; быстро, но нужны данные. По
RoomCraft (2025): чем больше ограничений, тем чаще коллизии убирают мебель; помогает
порядок размещения поиском в глубину по сети отношений и подстройка весов при
конфликте. Источники:
[Constrained Furniture Layouts (arXiv)](https://arxiv.org/pdf/1711.10939),
[RoomCraft (arXiv)](https://arxiv.org/abs/2506.22291),
[Lampert, генерация интерьеров (HSLU)](https://blog.hslu.ch/games/files/2021/11/Manuel_Lampert_Procedural_generation_of_interior_settings.pdf)
(PDF я до текста не вскрыл — по аннотации поиска).

**Godot: размножение пропов.** `MultiMeshInstance3D` быстр, но все экземпляры —
один меш, и отсекается он целиком (либо весь виден, либо нет): для мебели с
разными мешами выигрыша мало, а для сотен одинаковых мелких предметов (ящики,
бумаги) годится, разбитый на куски по комнатам. Аддоны для рассыпания
(MultiMesh Scatter, Yamms и др.) ориентированы на ландшафт и редактор, не на
комнаты. Источник: [ScatterShot](https://store.godotengine.org/asset/helvetica-scenario/scattershot/).

## Предложение (не решение)

1. **Таблица обстановки на тип комнаты** (аналог таблицы популяции Qud) —
   `.tres` в `data/`: список «пропов/групп» с весами, числом, правилами (у стены,
   в углу, лицом к центру, не ближе N м к сокету). Правится в редакторе, не в
   коде, как каталог типов.
2. **Крупное — решателем правил, мелкое — рассыпанием.** Этапы по образцу
   билдеров Qud: (а) якоря — крупная мебель/оборудование по приоритету (стол,
   стеллаж, койка, шкаф) с зонами свободы и «родителями»; (б) группы — авторские
   кластеры («стол + 4 стула») как единые префабы; (в) мелочь — рассыпание на
   поверхностях и полу; (г) интерактивы и находки — по маркерам, как
   `EssenceSpot*`; (д) состояние — повреждённость («разрушенные версии» как третья
   ось, [[Типы комнат]]).
3. **Источники пустоты: пока решаем вручную.** Для комнат, уже нарисованных
   руками, остаются маркеры-слоты (`PropSlot*`) — выбор содержимого слота по
   таблице типа, как у `EnemySpawn*`. Решатель нужен там, где коробка без
   авторской внутренности (сборная под любой footprint). Сперва маркеры, потом
   решатель — по цене и риску.
4. **Определённость.** Бросок на слот/объект — `hash([run_seed, depth, node_id,
   marker])`, расстановка обязана быть функцией сида: слой, собранный заново,
   возвращает те же столы на те же места (как ростер врагов).
5. **Геометрия и навмеш.** Пропы с коллизией на `static_colliders` попадают в
   запекание навмеша слоя — расставлять надо **до** `LayerNavigation.bake`
   (в конце `spawn`/`spawn_async`); зона перед сокетами обязана остаться
   свободной (проверка `room_shell_check` уже есть), и добавить проверку, что
   расстановка не перекрывает путь между дверями комнаты (достижимость по навмешу).
6. **Производительность.** Прятать пропы вместе с комнатой (`reveal_around`
   уже прячет детей корня комнаты); общие материалы/палитра, атлас на группу
   мелких пропов ([[Blender-Godot пайплайн]] §10); MultiMesh — только для
   одинаковых мелочей и по комнатам; исследование стоимости — вместе с
   [[Враги — двери и симуляция слоя]] (общий бюджет кадра на UHD 630).

## Открытые вопросы

- Решатель правил или только маркеры на первой итерации.
- Кто пишет таблицы обстановки: набор по типам нужен к первому типу после
  `lab`; арт-бюджет на пропы по типам (арсенал, склад, столовая…) — отдельная
  оценка у художника.
- Как пропы связаны с вариантами типа по слою и с «разрушенностью» (третья ось).
- Как соотносятся с ползунком стабильности: хаос — «детали перепутаны»,
  порядок — обстановка по правилам ([[Разнообразие помещений и стабильность
  комплекса]]).

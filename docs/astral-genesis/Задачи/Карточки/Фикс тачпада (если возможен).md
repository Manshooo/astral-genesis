#bug

## Диагноз (сверено с кодом)

**Бага в движке нет.** Взгляд камеры не зависит от движения:
- `E_Player._input` копит `mouse_delta` из `InputEventMouseMotion.relative`;
- `S_FPSLook` применяет его к повороту игрока/питчу камеры;
- движение (`WASD`) читается опросом `Input.get_vector` в `S_PlayerInput` — с камерой никак не связано.

Настройки устройств ввода в `project.godot` — дефолтные, ничего не блокирует.

Причина — **на уровне ОС**: в Ubuntu 22.04 (libinput/GNOME) по умолчанию включён
**«disable-while-typing» (DWT)**. Пока зажаты клавиши движения, авто-повтор клавиш
трактуется системой как «печать», и тачпад отключается — события движения мыши не
доходят до приложения, поэтому камера стоит. Это поведение драйвера **ниже уровня
движка**: приложение его не переопределяет (отсюда «(если возможен)» в названии).

## Решение — workaround для игрока (Ubuntu/Linux)

Отключить «disable-while-typing» в системе:

- **GNOME (Wayland/X11):**
  `gsettings set org.gnome.desktop.peripherals.touchpad disable-while-typing false`
  (или Настройки → Мышь и тачпад → выключить «Отключать тачпад при наборе текста»).
- **X11 напрямую через libinput:**
  `xinput list` → найти тачпад →
  `xinput set-prop "<имя тачпада>" "libinput Disable While Typing Enabled" 0`.

Внешняя мышь этим не затронута — баг проявляется только на тачпаде ноутбука.

**Статус:** не баг движка; правок в коде не требует. Альтернативные схемы ввода
(поворот камеры клавишами / стик геймпада) — отдельная задача геймплея, если
понадобится играбельность на тачпаде без правки системных настроек.

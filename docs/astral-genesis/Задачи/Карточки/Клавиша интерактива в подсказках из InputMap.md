# Клавиша интерактива в подсказках из InputMap

Целевая версия: **v0.4.0** (жёстко связано с ребайндингом — см. ниже).

Подсказка интерактива должна **сама подтягивать** клавишу из InputMap по имени

действия, а не хранить её текстом в каждой подсказке вручную.

## Сейчас

- `C_Interactable` несёт `action_name` (по умолчанию `&"interact"`) и

`prompt_text` (см. [[Взаимодействие]]).

- Ввод жёстко завязан на имя действия: `S_InteractInput` слушает

`Input.is_action_just_pressed("interact")`.

- Система показа `prompt_text` — задача [[v0.3.0]] («Подсказки к интерактивным

объектам»); клавишу в ней логично не писать руками.

## Что нужно

- При рендере подсказки резолвить клавишу из действия (`C_Interactable.action_name`)

через `InputMap.action_get_events(action)` → `event.as_text()` (или аккуратный

формат для клавиатуры/мыши), подставлять в шаблон вроде `«[{key}] Открыть»`.

- Работать для любого действия, не только `interact` (напр. `snatch_body` — ЛКМ).

## Почему v0.4.0

Прямая зависимость от «Настройки управления — ребайндинг клавиш» ([[v0.4.0]]):

после переназначения подсказка обязана показывать **новую** клавишу автоматически.

Без этого — рассинхрон. Если ребайндинг уедет позже, эту задачу можно двигать

вместе с ним.

## Нюансы

- У действия может быть **несколько** событий (клавиша + геймпад) — решить, какое

показывать (или все).

- Мышь: `ЛКМ`/`ПКМ` форматировать читаемо, не «Left Mouse Button».

- Обновление подсказок **на лету** при смене раскладки — подписаться на

`SettingsManager.settings_changed` (пересобрать текст).

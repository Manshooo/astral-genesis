# Визуал захваченного тела

Целевая версия: **v0.4.0**. Статус: **реализовано, на тестировании**.

После захвата капсула оставалась **белой** (дефолтный риг игрока), хотя у
`E_Body` капсула зелёная: по модели захвата душа-риг **поглощает** тело и удаляет
его сущность, а `_embody` переносил только трансформ и здоровье.

## Как сделано

Из развилки карточки — **копировать облик на риг**, а не переносить узел тела.
Перенос узла спорил бы с инвариантом «`E_Player` — единственная управляемая
сущность» и сломал бы обводку, которая ищет дочерний узел строго с именем
`MeshInstance3D`.

Связка сделана по документированному в `CLAUDE.md` приёму «компонент-запрос к
презентации» (как `C_Highlighted` → `O_OutlineVisual`):

- **`C_BodyVisual`** на душе-риге: `mesh` + `material_override` захваченного тела
  и `restore_mesh` / `restore_material` — куда откатиться.
- **`O_BodyVisual`** применяет облик по добавлению компонента и возвращает
  прежний по снятию. Меняет **только** `mesh` и `material_override` на том же
  самом узле `MeshInstance3D`, не подменяя и не пересоздавая его, — иначе
  обводка перестала бы находить геометрию.
- `S_BodySnatch._embody` вешает компонент, `O_ExpelFromBody._expel` снимает.
  Система захвата про меши не знает — она только просит.

### Откуда берётся облик

Из **сцены самого тела** (`MeshInstance3D` → `mesh`, `material_override`), а не из
отдельно объявленных данных. Дублировать меш ещё и в компоненте — гарантированный
рассинхрон при первой же правке сцены: меш, который игрок видел в мире, и меш,
который он получает при вселении, обязаны быть одним и тем же.

### Пересадка из тела в тело

Отдельная ловушка. Командный буфер **коалесцирует** remove+add компонента одного
типа в один переезд архетипа, поэтому наблюдатель может не увидеть снятие
старого `C_BodyVisual`. Если бы новый компонент запоминал «прежний вид» сам, он
запомнил бы облик ПРОШЛОГО ТЕЛА — и к призраку игрок больше никогда не вернулся
бы.

Поэтому: `S_BodySnatch` переносит `restore_*` из старого компонента в новый
руками, а `O_BodyVisual` не перезаписывает уже заполненный откат.

## Проверено

Одиночный захват:

```
до захвата: риг=CapsuleMesh (h=2.0) тело=CapsuleMesh (h=1.8) — разные: true
цвет рига: (1.0, 1.0, 1.0, 1.0)   цвет тела: (0.45, 0.53, 0.4, 1.0)
после захвата: embodied=true, меш рига == меш тела: true, цвет (0.45, 0.53, 0.4)
обводка цела: узел MeshInstance3D тот же: true
после развоплощения: меш рига == призрачный: true, цвет (1.0, 1.0, 1.0, 1.0)
```

Цепочка (БФЖ → красное тело → синее тело → гибель):

```
вселились в тело A (красное): цвет рига (0.9, 0.2, 0.2)
вселились в тело B (синее):   цвет рига (0.2, 0.3, 0.9)
после развоплощения: цвет (1.0, 1.0, 1.0), вернулись к БФЖ: true
```

## Осталось

- **Облик БФЖ — та же белая капсула.** Задача была про «принять вид тела»;
  отдельного «призрачного» вида (прозрачность, свечение) у рига нет — это уже
  [[Подумать над обводкой]] / арт.
- Переносится только меш и материал. Размер капсулы коллизии, скорость и прочие
  повадки тела — [[Характеристики захватываемых тел]] (v0.5.0).

# Подумать над обводкой

Целевая версия: **v0.4.0**. Статус: **реализовано, на тестировании**.

Задача была про **эргономику авторинга**: создавая новый интерактивный объект, не
должно приходиться думать о его иерархии. Визуальное качество самой обводки —
отдельная задача, [[Обводка силуэтом через постэффект]].

## Что было

`O_OutlineVisual` искал геометрию по правилу: сама сущность, если она
`GeometryInstance3D`, иначе — дочерний узел с именем **строго** `MeshInstance3D`.

Замер показал, что сломано ничего не было: и дверь, и инкубатор проходили по
первому правилу, причём инкубатор **случайно** — скрипт навесили на узел из
`.glb`, который оказался мешем. Ловушка ждала первого импортированного `.glb`,
где сущность `Node3D`, а меши внутри: `_find_geometry` вернул бы `null`, и
наблюдатель просто вышел бы — **молча**.

## Что стало

Взят предложенный вариант — «все меши поддерева плюс необязательное
переопределение».

- **`RS_EntityVisuals`** — одно место, где живёт правило поиска:
  - `geometries(entity)` — сама сущность, если она геометрия, плюс **всё
    поддерево**, имена узлов не значат ничего;
  - `primary(entity)` — основной меш, для тех, кому «все» бессмысленно.
  - Поиск с `owned = false`, иначе меши из инстанцированной под-сцены (ровно
    случай импортированного `.glb`) не находятся.
- **`O_OutlineVisual` красит ВСЕ найденные меши.** Побочный выигрыш: составной
  объект (рама + полотно + ручка) подсвечивается целиком, а не наполовину.
- **`C_VisualRoot { path }`** — необязательное переопределение. По умолчанию
  компонента нет и не нужно; вешается, только когда автоматика промахивается:
  есть меши, которые красить не надо, или красить надо строго один узел. Путь —
  относительно сущности; битый путь даёт предупреждение и откат к обычному
  поиску, а не тихую поломку.
- **Промах больше не молчит:** нет ни одного `GeometryInstance3D` — предупреждение.
- **Дубль устранён.** `_find_geometry` жил копией в `O_OutlineVisual` и
  `O_BodyVisual`; теперь оба зовут `RS_EntityVisuals`, и правило не может
  разъехаться. Ровно та же болезнь была у геометрии дверей, пока её не свели в
  `RS_RoomLayout`.

## Проверено

```
существующий интерактив (сущность — меш):     мешей 1 → подсвечено 1, снято 1
Node3D с двумя мешами внутри (старое правило
промахивалось):                               мешей 2 → подсвечено 2, снято 2
C_VisualRoot с битым путём:                   предупреждение + откат, мешей 2
C_VisualRoot → «Модель/Корпус»:               мешей 1 → подсвечено 1, снято 1
сущность вовсе без мешей:                     предупреждение вместо тишины
```

Отдельно проверено, что подмена облика тела не задета переездом на общий поиск:
`primary(рига)` — это его `MeshInstance3D`, захват меняет меш, обводка поверх
подменённого облика ставится и снимается, меш при этом цел, развоплощение
возвращает облик БФЖ.

## Осталось

- ~~Обводка по-прежнему `material_overlay` на каждом меше~~ — закрыто в
  [[Обводка силуэтом через постэффект]] (v0.6.0): обводка переехала на маску, и
  все три следствия ушли вместе с overlay-материалом. `RS_EntityVisuals` там
  переиспользован как есть — правило поиска мешей не менялось, поменялось только
  то, что с найденными мешами делают (слой видимости вместо материала).
- `C_VisualRoot` пока нигде не используется: сцен, где надо красить не всё, ещё
  нет. Проверен синтетикой.

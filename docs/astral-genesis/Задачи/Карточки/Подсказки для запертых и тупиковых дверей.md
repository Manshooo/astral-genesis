# Подсказки для запертых и тупиковых дверей

Целевая версия: **v0.4.0**. Статус: **реализовано, на тестировании**.

Игрок должен понимать, почему дверь не открывается. Обратной связи не было —
две ситуации, обе закрыты.

## 1. Запертая дверь (`locked_by`)

Раньше `A_TravelThroughDoor.execute` при `C_DoorPortal.is_locked()` печатал в
консоль (`print("Дверь заперта: нужен '%s'"...)`) — игрок этого не видел.

Теперь:
- `RunManager._bind_doors` ставит запертой двери подсказку **«Заперто»** — она
  видна ещё до нажатия;
- нажатие даёт экранное сообщение **«Заперто. Нужен ключ доступа к уровню»**
  (`A_TravelThroughDoor.KEY_NAMES` переводит `locked_by` в человеческое имя).

Ключей в игре по-прежнему нет нигде, так что заперто = закрыто наглухо — см.
[[v0.4.0]] «Переработать Level Access Key» и инвентарь ключей.

- Файлы: `src/resources/interaction/a_travel_through_door.gd`,
  `RunManager._bind_doors`.

## 2. Дверь, которая никуда не ведёт (запечатанный слот)

Когда у комнаты слотов-дверей больше, чем рёбер графа, лишние **запечатываются**.
Раньше `RunManager._seal_door` ставил `C_Interactable.enabled = false` — и такая
дверь вообще не подсвечивалась и молчала: игрок не понимал, декор это или баг.

Из трёх вариантов (оставить интеракцию без перехода / отдельный визуальный маркер
/ отдельный флаг «sealed») выбран **первый**:
- `_seal_door` штампует **пустой `C_DoorPortal`** — пустой `target_node_id` уже
  означал «проём запечатан» по контракту компонента, отдельный флаг не нужен;
- `C_Interactable.enabled` остаётся `true`, подсказка — **«Прохода нет»**, а
  новый флаг `show_key_hint = false` убирает из неё бессмысленный префикс
  клавиши («Прохода нет», а не «[F] Прохода нет»);
- нажатие даёт сообщение «Прохода нет: проём заварен».

Визуальное «заваривание» (арт) — отдельная задача.

- Файлы: `RunManager._seal_door` / `_set_door_prompt`
  (`src/autoloads/run_manager.gd`), `src/components/gameplay/c_interactable.gd`.

## Общее: канал экранных сообщений

Разовую реплику на нажатие показывает новая связка по паттерну
«компонент-запрос к презентации» (как `C_Highlighted` → `O_OutlineVisual`):

- `C_ScreenMessage { text, remaining }` — логика вешает на игрока;
- `hud_message.gd` — рисует по сигналам мира `component_added`/`component_removed`;
- `S_ScreenMessage` — тикает `remaining` и снимает компонент через `cmd`.

Повторный показ = remove + add компонента: прямая запись в поля миру не
сигналится, и HUD не увидел бы новый текст.

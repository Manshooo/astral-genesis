# Карта комплекса

Целевая версия: **v0.4.0** (то, что на доске значилось как «Добавить карту
комплекса/уровня»).

## Оценка: данные уже есть

Хорошая новость — почти всё, что нужно карте, уже лежит готовым:

| Что нужно | Где уже есть |
|---|---|
| Полный граф комплекса | `RS_LevelGraph.nodes` — строится целиком при входе в забег |
| Где игрок сейчас | `RunManager.current_node_id` / `current_depth` |
| Что игрок уже видел | `WorldSave.visited_node_ids` — пишется на каждой смене комнаты |
| Связи между комнатами | `RS_LevelNode.connections` (+ `locked_by` для запертых) |
| Раскладка комнат в плоскости | `RunManager._plan_layer` — 2D-клетки по этажам |
| Экран поверх игры | `UIManager.push_screen` + `C_UIBlocked`, как дерево навыков |

Отдельного «сбора данных» задача не требует. Это выгодно отличает её от
большинства оставшихся.

### Одно техническое ограничение

`_plan_layer` требует **инстансы** комнат: стороны дверей берутся из геометрии
(`RS_RoomLayout.door_direction`). Поэтому готовая раскладка существует **только
для загруженного слоя** — нарисовать по ней соседние слои не выйдет.

Лечится дёшево: направления дверей зависят только **от сцены**, не от узла, — их
можно посчитать один раз и закэшировать `scene_path → стороны`. Тогда `_plan_layer`
можно гонять для любого слоя без спавна, а заодно ускорится сам спавн (сейчас
каждая комната инстанцируется, чтобы посчитать двери). Такой кэш уже полу-есть в
`gen_verifier._doors_in_scene`.

## Варианты «что показывать»

**A. Список комнат.** Текстом: где я, куда ведут двери. Час работы, но на вопрос
«где что есть» не отвечает — карта нужна как раз ради пространственной картины.
Годится разве что как отладка.

**B. Схема текущего слоя.** Этажи слоя, комнаты по клеткам `_plan_layer`, линии
связей, отметка «я здесь», посещённые/непосещённые. Использует готовую раскладку
как есть, ограничения из предыдущего пункта не задевает. **Самый дешёвый
настоящий вариант.**

**C. Схема всего комплекса.** Пять слоёв, вертикальные связи через порталы.
Нужен кэш направлений (см. выше) либо огрублённая раскладка для незагруженных
слоёв — для них точность и не важна, важна топология.

**D. Мини-карта в HUD.** Постоянно на экране. Для комнатной структуры проигрывает
экрану: комнат немного, а важны **связи**, которые на мини-карте не помещаются.
Не рекомендую как первый шаг.

## Варианты «откуда берётся»

**1. Доступна с самого начала.** Просто, но обесценивает исследование: смысл
блуждать по лабиринту, если он сразу нарисован.

**2. Улучшение у [[Артефакт «Архитектор»|Архитектора]]** — идея из лора, и она
хорошо ложится на уровни детализации:

| Уровень | Что видно |
|---|---|
| нет улучшения | ничего, только текущая комната |
| 1 | посещённые комнаты текущего слоя |
| 2 | весь текущий слой, включая непосещённые |
| 3 | весь комплекс |
| 4 | содержимое: типы комнат, где выход, где заперто |

Лорное объяснение бесплатное: знать, где что есть, можно ровно настолько,
насколько восстановлена связь с тем, кто комплекс и строит.

**3. Инженерный стол в лаборатории** — место, где улучшением распоряжаются.
Не альтернатива Архитектору, а вторая половина: Архитектор — *источник*, стол —
*место*. Подробнее в карточке Архитектора.

## Предложение

Делать **B + заготовку под 2**: карта текущего слоя, но за одним флагом
доступности и с уровнем детализации как параметром отрисовки. Тогда появление
Архитектора не потребует переписывать экран — только выдавать уровень.

Порядок:

1. экран карты (`UIManager`), действие открытия в `InputMap` + `REBINDABLE_ACTIONS`;
2. отрисовка текущего слоя через `_draw()` (узлов ~12 на слой, обычный `Control`
   справится; узлы-кнопки избыточны);
3. посещённые/непосещённые из `visited_node_ids`, «я здесь» из `current_node_id`;
4. запертые связи рисуем иначе — данные (`locked_by`) уже есть;
5. **потом** кэш направлений дверей → вариант C;
6. **потом** уровни детализации от Архитектора.

## Открытые вопросы

- Ставить карту на паузу (как дерево навыков) или показывать поверх живой игры?
- Показывать ли непосещённые комнаты «серым силуэтом» или не показывать вовсе —
  это же и есть разница между уровнями 1 и 2.
- Хранить уровень доступа в `WorldSave` или в `SkillManager` (см. карточку
  Архитектора про переиспользование машинерии прокачки).

# Баг — тела монстров без текстур в экспортированной сборке

Целевая версия: **v0.6.0**. Найдено живым прогоном релизной сборки v0.5.0:
`e_body_walker`/`e_body_crawler`/`e_body_hound` теряют текстуру в экспорте, хотя
в редакторе выглядят нормально.

## Симптом

Работает в редакторе (в т.ч. на другой машине после экспорта — сама сборка
запускается штатно), но тела монстров выходят без текстуры именно в
экспортированном билде. Единственное место в проекте, где вообще есть настоящие
UV-текстуры, а не плоский `albedo_color` — см.
[[Текстурный пайплайн и раскраска ассетов]] о состоянии остального проекта.

## Диагноз (не подтверждён визуально — нужна дальнейшая проверка)

Меши тел приходят не напрямую из `monsters.glb`, а из **сохранённых во внешние
файлы** `assets/monsters/models/monsters_body.res` (и `..._half_body.res`,
`..._headog.res`) — так три сцены тел делят один и тот же меш без копий. Это
настроено `_subresources.meshes.*.save_to_file` в `monsters.glb.import`.

Материалы при этом **не извлекаются отдельно**: `materials/extract=0`. Текстуры
глб экспортируются штатно (`gltf/embedded_image_handling=1` — «Extract
Textures», уходят во внутренний кэш импорта), но при `materials/extract=0`
привязка материала на сохранённом меше ссылается на материал, который остаётся
**внутренним подресурсом импортированной сцены**, а не самостоятельным
`res://`-файлом. Это известная ловушка Godot: «Save to file» у меша не делает
таким же самостоятельным материал, на который меш ссылается, если материал сам
отдельно не извлечён — ссылка не обязана пережить перерезолвку на чужой машине/
чистом импорте, хотя геометрия (она самодостаточна) переживает. Ровно то
расхождение, которое видно: меш на месте, текстуры нет.

Экспериментально (в этой карточке, отменено, не закоммичено): включение
`materials/extract=1` с `materials/extract_path` меняло содержимое всех трёх
`.res`-мешей при переимпорте — то есть привязка материала на них ДЕЙСТВИТЕЛЬНО
зависит от этого флага, гипотеза не на пустом месте. Но `--headless --import`
не создал ни одного файла материала по указанному пути: похоже, извлечение
материалов Godot управляется через `_subresources.materials.*` (по аналогии с
`_subresources.meshes.*` для мешей), а этот раздел заполняется диалогом
«Advanced Import Settings» в РЕДАКТОРЕ (перечисляет материалы по именам из
самого glTF) и не появляется от одной только правки `.import`-файла руками.
Дальше в headless — тупик: нужен редактор, чтобы увидеть список материалов и
включить извлечение по каждому, и нужен визуальный прогон (рендер), чтобы
подтвердить, что текстура действительно появилась в экспорте — ни то, ни другое
недоступно в этой сессии.

## Что нужно сделать

1. Открыть `monsters.glb` в редакторе → **Advanced Import Settings** → включить
   извлечение материалов (по аналогии с уже включённым «Save to file» у мешей).
2. Переимпортировать — три `.res`-меша должны обновиться и приобрести ссылку на
   новые самостоятельные файлы материалов.
3. Собрать релизный экспорт (`dev/release.ps1`) и визуально проверить все три
   тела — это тот самый шаг, который headless не заменяет.
4. Если гипотеза не подтвердится — материалы всё-таки не единственная причина,
   смотреть на `gltf/texture_map_mode` и формат VRAM-компрессии в
   `export_presets.cfg` для профиля текстур (тоже кандидат: экспорт мог просто
   сжать текстуру в формат, который рантайм не умеет собрать без доп. импорта).

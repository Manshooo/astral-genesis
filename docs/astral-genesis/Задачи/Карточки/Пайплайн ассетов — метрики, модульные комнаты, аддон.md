# Пайплайн ассетов — метрики, модульные комнаты, аддон

Целевая версия: **v0.7.0**. Начато 26.09 разбором `buildings.blend`, аддонов
Blender и Godot и раскладки `assets/`.

## Решения 26.09

- **Масштаб:** гигантизм архитектуры намеренный, мебель человеческая. Два эталона —
  клетка и тело ([[Метрики и кит]] §1).
- ~~**Комнаты:** модульно в Blender, на выходе те же пять монолитов на стиль.~~
  Снято вечером 26.09, см. ниже.
- **Клетка — куб 8 м** (вечер 26.09): комнаты из целого числа клеток, этажи —
  уровни одной 3D-сетки, коридор ~5 м против 8 м у комнаты, стена внешней гранью
  на границе клетки, сокет по центру грани клетки, проём 2.75 × 4.25 без порога,
  дверь рисуется под проём. **Комнаты собираются в Godot по маске сокетов**: у
  комнаты 2×2 восемь сокетов, монолитами это не выпустить. Контракт —
  [[Метрики и кит]]; перевод генератора — [[Сетка уровня — генерация на 3D-сетке]].
- **Godot MCP — Beckett**, плагин в редакторе (PR #55).
- **Архитектура раскрашивается** палитрой + детальным слоем + декалями; трим-лист
  отложен ([[Визуальный стиль и текстуры]]).
- **Исходники** — отдельный арт-репозиторий на Git LFS ([[Blender-Godot пайплайн]] §13).
- **Импосторы отвергнуты** — выигрыша при таком полигонаже и камере от первого
  лица нет ([[Визуальный стиль и текстуры]] §6).

## Порядок работ

1. [x] Документы: [[Метрики и кит]], [[Визуальный стиль и текстуры]], правки
   [[Blender-Godot пайплайн]] (этапы, нейминг §4.3, арт-репозиторий §13, хвосты

2. [x] **Прототип** (26.09) — в арт-папке `_proto/`: `kit_reference.blend`,
   `room_kit_proto.blend` и скрипт `build_room_kit_proto.py`, который собирает
   оба с нуля.
   - **Стиль C разрезать на модули нельзя**, хотя планировали начать с него: это
     восьмиугольник в квадрате, и он несимметричен на 4–11 см. Центры граней
     (−5.89, −5.78) против (5.78, 5.89), диагональные панели у C_1 и C_4 нарезаны
     по-разному. Поэтому прототип собран из чистых болванок по контракту клетки
     (стиль `P`), а стили A/B/C перемоделируются модулями.
   - **Техника подтвердилась:** нод-группа `GN_room_assembler` (входы N/E/S/W и
     три объекта стиля) даёт пять вариантов. Экспорт glTF с применёнными
     модификаторами — у каждого **один узел, один меш, один примитив**,
     `MAT_building`, развёртка на месте, свойства коллизий в `extras`, геометрия
     внутри ±9 м, проёмы на ожидаемых гранях. Валидатор аддона — 0 ошибок.
   - **Грабли Blender 5.** Входы модификатора Geometry Nodes больше не `mod[id]`:
     значение лежит в `mod.properties.bl_system_properties_get()["inputs"][id]["value"]`.
     Свойства аддона (`c.godot`) тоже системные: записать их можно только при
     загруженном аддоне, словарь `c["godot"]` он не видит.
   - Импорт в Godot не прогонялся: `.glb` по структуре такой же, как у нынешних
     комнат.
3. [x] **Аддон `godot_pipeline` 1.4.0** — PR #54 (26.09), ждёт влития:
   - материалы берутся и из вычисленного меша — сборщик на Geometry Nodes
     получает ссылку `use_external`;
   - `GP_CollisionPreview` на время экспорта снимается со слотов прокси и в `.glb`
     не попадает. **Мало было не ссылаться на него:** пока он лежал в файле,
     «Extract Once» заводил `.tres` заново на каждом холодном импорте. Из 8
     лежащих `.glb` он вырезан, ссылки из 30 `.import` и сам `.tres` удалены
     (§16 п. 10);
   - ренеймер берёт базу имени после токена `MAT_` и чинит уже испорченные имена
     (§16 п. 11 — сами карты артефакта ещё надо переименовать);
   - валидатор: объект с именем своего `.glb`, данные меша с чужим именем, и
     контракт клетки — поля профиля *Cell Size* / *Height Limit* (18 и 20 м в
     `godot_pipeline.json`). Верх пола на `z = 0` не проверяется: где пол, аддону
     не знать. На `buildings.blend` проверка повторила таблицу замеров из
     [[Баг — швы на стыках коридоров]];
   - профиль Interactive: тип корня `None` (§16 п. 4).

   После влития: перезагрузить аддон в Blender и нажать **Load from Project** в
   его настройках — иначе у профилей в Blender не будет чисел кита.
4. [x] **Арт-репозиторий** (26.09) —
   [Manshooo/astral-genesis-art](https://github.com/Manshooo/astral-genesis-art),
   приватный: `.blend`, `textures/`, `_proto/`, 29 файлов в LFS (60 МБ). Кадры
   `render/` (1.3 ГБ) и старые монолитные `export/` в git не взяты — это выход, а
   не исходник. Репозиторий заведён **на месте**, в прежней арт-папке: так ни один
   файл не переехал, и относительные пути `.blend` не сломались. На этой машине
   `lfs.setlockablereadonly=false` — иначе LFS сделал бы все `.blend` доступными
   только для чтения до взятия блокировки, и открытый файл перестал бы
   сохраняться. Блокировки при этом работают: пуш чужого заблокированного файла
   сервер отклонит.

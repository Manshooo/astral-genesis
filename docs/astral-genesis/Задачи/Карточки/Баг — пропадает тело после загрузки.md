# Баг — пропадает тело после загрузки

Целевая версия: **v0.5.0**. Приоритет: **высокий** — ломает связку двух только что
закрытых фич (захват тела из v0.3.0 и сейв/загрузка из v0.4.0).

> [!done] Починено в v0.5.0
> Сейв научился воплощению; подробности — в разделе «Как починено» ниже и в
> [[Цикл забега]].

## Симптом

Сохранился, будучи **во плоти** → загрузился → БФЖ снова призрак, тело исчезло.

## Причина (сверено с кодом)

Состояние воплощения **не сериализуется вообще**. `RS_WorldSave` хранит только:

```
world_seed, death_count,
run_in_progress, current_node_id, visited_node_ids, lifespan_remaining
```

Ни `C_Embodied`, ни `C_Health` там нет — по всему `src/autoloads/` и
`rs_world_save.gd` упоминаний `C_Embodied` ноль.

Дальше складывается два эффекта:

1. **Душа грузится призраком.** `RunManager._spawn_player()` инстанцирует свежую
   `E_Player`, чья идентичность приходит из `define_components()` — это
   `C_BodySnatch` + `C_Lifespan`, и только. `_restore_player_progress()`
   восстанавливает **единственное** поле — `C_Lifespan.current`. Значит после
   загрузки `C_Embodied`/`C_Health` отсутствуют по определению → развоплощён.
2. **Тела в мире тоже нет.** При захвате исходная сущность поглощается
   (`cmd.remove_entity(body)` в `S_BodySnatch._embody`), а комнаты
   восстанавливаются из сида — то есть тело либо возродится нетронутым (как будто
   его не захватывали), либо, если оно было заскриптовано в комнате, встанет на
   место. Своё «съеденное» тело не восстанавливается никак.

## Что решить при починке

- **Что именно сохранять:** факт воплощения + текущее HP + облик
  (`C_BodyVisual`), либо ссылку на пресет тела, из которого всё это выводится.
  Второе устойчивее к правкам баланса и меньше дублирует данные.
- **Что делать с телом в комнате:** помечать в сейве «это тело уже поглощено»,
  чтобы при восстановлении слоя не появился дубликат того, в ком ты сидишь.
- Симметрия с [[Характеристики захватываемых тел]]: как только у тела появятся
  статы сверх `max_health`, сохранять придётся **их набор**, а не одно число.
  Разумно чинить после того, как решена модель статов, либо сразу закладывать
  «сохраняем id пресета тела».

## Как починено

Выбран второй вариант из «что решить»: сохраняется **ссылка на пресет тела**, а
не его данные. В `RS_WorldSave` добавлены `body_scene_path` (пусто = призрак),
`body_health` / `body_health_max` и `consumed_body_ids`.

- **Что переживает загрузку.** `C_Embodied` перестал быть пустым маркером и
  несёт `body_scene_path`; `S_BodySnatch` заполняет его при вселении. На
  контрольной точке `RunManager._checkpoint` разбирает душу на числа — сам
  автолоад сейва про ECS по-прежнему не знает ничего.
- **Облик** восстанавливается из сцены тела (`E_Body.visual_of_scene`), а не из
  сейва: меш — часть сцены, и второй источник правды о внешности разъехался бы с
  первой правкой. Заодно чтение геометрии переехало на `RS_EntityVisuals`, то
  есть на то же правило, по которому `O_BodyVisual` этот облик надевает; раньше
  захват искал узел строго по имени `MeshInstance3D`.
- **HP** сохраняются числами — и текущее, и потолок: потолок правят скиллы,
  пересчитывать его из сцены было бы неверно.
- **Тело в комнате.** `RunManager` штампует на телах `C_BodyOrigin` с id вида
  `«узел графа»/«путь узла в комнате»` (как раздаёт дверям `C_DoorPortal`),
  захват помечает id съеденным сразу же, а спавн комнаты такие тела не
  регистрирует и освобождает узел.
- **Смежный дефект, найденный по дороге.** Восстановление обрезало
  `lifespan_remaining` по `max_duration`, хотя во плоти потолок равен
  `effective_max(true)` (60 против 120) — загрузка молча съедала бонус тела.
  Теперь воплощение восстанавливается до обрезки, и порядок описан в коде.

Проверено headless-прогоном: облик читается из сцены, новые поля переживают
`.tres`-раунд-трип (включая `Array[StringName]`), тело в хабе получает id
`L3_F0_room_0/Body`, восстановление возвращает `C_Embodied` + HP + облик без
обрезки запаса, а помеченное съеденным тело в перезапущенном забеге не
появляется.

# Документация: где живёт знание и как держать его правдой

Три места, у каждого своя работа, и ни одно не пересказывает другое:

| Место | Что в нём | Чего в нём нет |
|---|---|---|
| **Вики** `docs/astral-genesis/` | как устроена механика, инварианты, отвергнутые варианты, история решений | — единственный источник правды |
| **Код** | имена, которые сами говорят, что делают; пометка у строки, где решение неочевидно | описание механики, история, пересказ кода |
| **`CLAUDE.md`** | сводка инварианта «что нельзя» + ссылка в вики | объяснение «как работает» |

Одно и то же в двух местах — не подстраховка, а гарантированный рассинхрон.

## Комментарии: что остаётся в коде

Код документирует себя сам — именами функций, полей, констант. Комментарий
нужен только там, где читатель кода **споткнётся без него**:

- **Ловушка движка или библиотеки**: «Jolt на своём потоке — space-state только
  из `_physics_process`», «`preload` кастомного ресурса падает в экспорте
  (godotengine/godot#100100)».
- **Неочевидное ограничение решения**: «порядок обязателен — по нему идут
  броски общего rng», «`free()`, а не `queue_free()`: старый регион не должен
  дожить до нового слоя».
- **Обходной путь** — со ссылкой на причину (issue, раздел вики).
- **Шапка скрипта** — одна-две строки «зачем существует» + ссылка на раздел
  вики (`## [[Цикл забега]] §3` или путь). Не конспект раздела.
- `##`-описание у `@export` — подсказка инспектора: одна строка о смысле и
  единицах, не теория.

Удаляется:

- **Пересказ кода** («проходим по дверям и ставим замок») — это видно из кода.
- **История** («раньше было X», «до 08.10 …», «первая версия вешала …») —
  место ей в коммите и в вики. Оставить можно одну строку, если без неё
  следующий правщик вернёт старую ошибку: «не `C_PlayerInput` — с ним
  `execute_one()` находил врага вместо игрока».
- **Описание механики целиком** — если оно уже в вики, комментарий заменяется
  ссылкой; если в вики его нет — **сначала перенести в вики**, потом удалить.
  Знание не теряется ни при какой чистке.
- **Абзацы** там, где хватает строки. Длинный блок — сигнал, что текст хочет
  жить в вики.

Длина как ориентир, не закон: пометка у строки — 1–3 строки, шапка — до 3 строк
плюс ссылка.

## Навигация: где что описано

Полная карта — [references/doc-map.md](references/doc-map.md). Коротко:

| Нужно разобраться в… | Читать |
|---|---|
| модели ECS, «Правиле v9», ECS-паттернах | `how-to/GECS и правила движка.md` |
| генерации мира, слоях, дверях, переходах, сейве | `how-to/Цикл забега.md` |
| интерактивных объектах, луче, подсказках | `how-to/Взаимодействие.md` |
| захвате тела, характеристиках, стабильности и распаде | `how-to/Захват тела.md` |
| граблях инструментов редактора, шаблонах сущностей | `how-to/Редакторские инструменты.md` |
| звуке | `how-to/Звук.md` |
| слоях физики, теме UI, префиксах, ребайнде, настройках проекта | `Справка/Конвенции проекта.md` |
| CI, версиях, релизах | `how-to/Релизы и сборка.md` |
| что вообще уже реализовано | `Состояние проекта.md` |

Читать **до** правки подсистемы. Нет нужного описания — это пробел вики:
завести раздел там, где он должен быть по карте, а не восстанавливать логику из
кода молча.

## Сверка после изменения кода

1. **Объём.** `git diff` / `git log` от последней ревизии либо список файлов от
   пользователя.
2. **Вики.** По карте найти документ затронутой области и свести с новым
   поведением: профильный how-to, `Состояние проекта.md`, карточка в `Задачи/`.
   Не описывать несуществующее: откатанная или недоделанная фича в вики
   называется так, как есть.
3. **Комментарии затронутых `.gd`** — по правилу выше. Комментарий,
   ссылающийся на переименованное, поправить.
4. **`CLAUDE.md`** — только если стала неверной сама сводка или конвенция, или
   появился документ, которого нет в таблице «Документация — карта».
5. **Карточки.** Задача закрыта → карточка из `Задачи/vX.Y.Z.md` в
   `Задачи/Завершено/`; незапланированная работа → новая карточка.
6. **Ссылки:**

   ```bash
   python .claude/skills/docs-sync/scripts/check_doc_references.py
   ```

   Идентификаторы `C_*`/`S_*`/`E_*`/`O_*`/`RS_*`/`A_*` и пути, которых нет в
   коде (роадмап пропускается, `--include-roadmap` — с ним). Не автофикс:
   список проверяется глазами. `[[wikilinks]]` Obsidian на битой ссылке не
   падает — после переименования искать `[[старое имя` руками.

## Чистка комментариев (по запросу или файлу, который правишь)

```bash
python .claude/skills/docs-sync/scripts/comment_audit.py [пути] [--block 3] [--top 40]
```

Показывает длинные блоки и файлы, где комментариев больше четверти, — очередь
на чтение, не вердикт. Порядок по каждому файлу:

1. Найти раздел вики, который описывает этот скрипт (карта выше; в шапке
   скрипта часто уже есть ссылка).
2. Каждый блок длиннее пары строк разложить: пересказ кода — удалить; история —
   удалить или одной строкой-предостережением; описание механики — проверить,
   есть ли оно в вики: есть → ссылка, нет → дописать в вики, потом удалить;
   ловушка — сжать до строки у той строки кода, которой она касается.
3. Код не трогать: чистка комментариев не меняет поведения. Сторож —
   `python .claude/skills/docs-sync/scripts/code_unchanged.py` (код без
   комментариев против `HEAD`, выход 1 с диффом, если ушло что-то кроме
   комментария). Затем затронутые проверки или `pwsh dev/run_checks.ps1`.
4. Коммит — отдельно от функциональных изменений, область `Комментарии:` или
   `Документация:`.

## Границы

- Не переписывать стиль и структуру документа без необходимости — только факты.
- Не документировать будущее в `Состояние проекта.md` — для этого `Задачи/`.
- Не трогать `История.md` (лор), если не попросили явно.
- Не раздувать `CLAUDE.md`: любое добавление туда — сводка и ссылка.
- `addons/gecs/` — апстрим, его комментарии не наши.

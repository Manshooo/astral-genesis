# Как читать каждую секцию скрипта

Полное объяснение — читать при разборе конкретной секции, не всё сразу.
Короткая версия каждого пункта уже есть в `SKILL.md`; сюда идти за нюансом,
который меняет трактовку.

## GIT

Ветка, расхождение с origin (`ahead`/`behind` — если `behind > 0`, это не
просто цифра, а чужие коммиты, которых нет локально: `git fetch` и посмотреть,
что там, **до** любого push — см. навык `commit-message` и его же прецедент с
расхождением по `e_body_walker.tscn`), незакоммиченные файлы, **стэши**. Стэш —
почти всегда забытый хвост: не трогать и не ронять (`git stash drop`/`pop`) без
явной просьбы, просто назвать пользователю, что он есть и что в нём
(`git stash show -p stash@{N}`), — решение, нужен ли он ещё, принимает человек.

## РОАДМАП

Доска — Obsidian-kanban `docs/astral-genesis/Задачи/vX.Y.Z.md` текущей версии
(версия берётся из имени ветки `release/vX.Y.Z`). Колонка **«В работе» — это
буквально ответ на «что в работе прямо сейчас»**; если она пуста, а
незакоммиченные правки в git-секции есть — это расхождение стоит показать
пользователю прямо («в git есть незакоммиченное, а на доске в работе ничего не
значится»), не сглаживать. «К выполнению» и «Тестирование» — запланированное и
то, что ждёт живой проверки (`gameplay-testing` покрывает headless-часть,
«нужен живой прогон» в карточке — не покрывает). Если ветка не
`release/vX.Y.Z` — скрипт назовёт все доски, какие есть, вместо того чтобы
гадать.

## КОД — TODO/FIXME

Только буквальные маркеры в комментариях — высокая точность, без словесного
шума. Слова вроде «placeholder»/«черновой»/«ждёт» специально не грепаются
широко: в этом проекте «placeholder» часто законный архитектурный термин
(`RS_LevelGraph.PLACEHOLDER_ROOM_SCENE`, `RS_RoomPresetLibrary` про заглушку до
появления библиотеки пресетов), а не флаг недоделки — широкий grep по такому
даёт больше шума, чем сигнала. Настоящую «черновую» пометку видно по контексту
при чтении, не по регулярке.

## ДОКУМЕНТАЦИЯ — известные пробелы

Раздел «## …Известные пробелы» в `Состояние проекта.md`, вытянутый как есть —
это уже отсортированный человеком список, не пересчитывать заново. Полезно
сверить с TODO из предыдущей секции: если пробел в вики описан, а TODO в коде
на ту же тему нет (или наоборот) — стоит заметить расхождение, а не тихо
пройти мимо.

## СВЕРКА DOCS-SYNC

Отсюда и вызывается навык `docs-sync` — его же скрипт
`check_doc_references.py`, без дублирования логики. Если он находит что-то
новое (не из уже известного фонового шума — «GECS и правила движка.md» про
example_card_game, `S_EnemyAI` из «Известных пробелов») — это и есть хвост
уровня документации, им должен заняться `docs-sync`, не этот скилл.

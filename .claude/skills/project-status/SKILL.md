# Состояние проекта: срез, не диагноз

Четыре источника, которые никто не читает одновременно, хотя вместе они и
отвечают на вопрос «где мы сейчас»: git (что реально лежит в дереве и в
истории), kanban-доска текущей версии (что запланировано и что помечено «в
работе»), код (TODO, оставленные прямым текстом), вики (раздел «Известные
пробелы» — то, что сам проект уже назвал незакрытым). Скилл их не
интерпретирует за пользователя и не чинит — только сводит в один читаемый
срез, дальше решает человек.

## Быстрый прогон

```bash
python .claude/skills/project-status/scripts/scan_project_state.py
```

Печатает пять секций подряд: git, роадмап, TODO в коде, пробелы из вики,
сверка docs-sync. `--skip-doc-check`, если сверка документации в этот раз не
нужна (например, вопрос чисто про git/роадмап).

## Как читать каждую секцию

Полное объяснение с примерами и прецедентами —
[references/reading-guide.md](references/reading-guide.md); идти туда при
разборе конкретной секции, а не читать всё заранее. Здесь — суть на секцию:

| Секция | Суть |
|---|---|
| **GIT** | `behind > 0` — чужие коммиты, `git fetch` до push. Стэш — забытый хвост: назвать, не трогать без просьбы |
| **РОАДМАП** | Доска версии из имени ветки `release/vX.Y.Z`. «В работе» — буквальный ответ; пусто при непустом git — показать расхождение прямо |
| **TODO/FIXME** | Только буквальные маркеры в коде — без грепа по словам вроде «placeholder» (в проекте это законный термин, не флаг недоделки) |
| **Пробелы вики** | Раздел «Известные пробелы» уже отсортирован человеком — не пересчитывать; сверить с TODO на расхождение |
| **docs-sync** | Через `check_doc_references.py`, без дублирования. Новое (не фоновый шум) — хвост для `docs-sync`, не для этого скилла |

## Что делать с результатом

Не чинить ничего в рамках этого скилла. Роль — назвать три вещи пользователю
одним связным текстом, а не пятью необработанными логами:
1. что реально в работе (git + колонка «В работе», и явно сказать, если они
   расходятся);
2. что ближайшее по плану (верх «К выполнению», в порядке карточек на доске —
   порядок канбана в этом проекте уже приоритетный, «делать первым» помечено
   в самих карточках, не выдумывать свой);
3. какие хвосты обнаружились (стэши, TODO без карточки, пробел из вики без
   соответствующей задачи в бэклоге/доске, находки docs-sync) — и по каждому
   спросить или предложить конкретное действие (завести карточку, взять в
   работу, оставить как есть), а не просто перечислить и остановиться.

Если пользователь после среза просит взяться за что-то из хвостов или из
доски — это уже отдельная задача, не продолжение этого скилла.

# Состояние проекта: срез, не диагноз

Четыре источника, которые никто не читает одновременно, хотя вместе они и
отвечают на вопрос «где мы сейчас»: git (что реально лежит в дереве и в
истории), kanban-доска текущей версии (что запланировано и что помечено «в
работе»), код (TODO, оставленные прямым текстом), вики (раздел «Известные
пробелы» — то, что сам проект уже назвал незакрытым). Скилл их не
интерпретирует за пользователя и не чинит — только сводит в один читаемый
срез, дальше решает человек.

## Быстрый прогон

```bash
python .claude/skills/project-status/scripts/scan_project_state.py
```

Печатает пять секций подряд: git, роадмап, TODO в коде, пробелы из вики,
сверка docs-sync. `--skip-doc-check`, если сверка документации в этот раз не
нужна (например, вопрос чисто про git/роадмап).

## Как читать каждую секцию

- **GIT.** Ветка, расхождение с origin (`ahead`/`behind` — если `behind > 0`,
  это не просто цифра, а чужие коммиты, которых нет локально: `git fetch` и
  посмотреть, что там, **до** любого push — см. навык `commit-message` и его
  же прецедент с расхождением по `e_body_walker.tscn`), незакоммиченные файлы,
  **стэши**. Стэш — почти всегда забытый хвост: не трогать и не ронять
  (`git stash drop`/`pop`) без явной просьбы, просто назвать пользователю, что
  он есть и что в нём (`git stash show -p stash@{N}`), — решение, нужен ли он
  ещё, принимает человек.
- **РОАДМАП.** Доска — Obsidian-kanban `docs/astral-genesis/Задачи/vX.Y.Z.md`
  текущей версии (версия берётся из имени ветки `release/vX.Y.Z`). Колонка
  **«В работе» — это буквально ответ на «что в работе прямо сейчас»**; если
  она пуста, а незакоммиченные правки в git-секции есть — это расхождение
  стоит показать пользователю прямо («в git есть незакоммиченное, а на доске
  в работе ничего не значится»), не сглаживать. «К выполнению» и
  «Тестирование» — запланированное и то, что ждёт живой проверки
  (`gameplay-testing` покрывает headless-часть, «нужен живой прогон» в
  карточке — не покрывает). Если ветка не `release/vX.Y.Z` — скрипт назовёт
  все доски, какие есть, вместо того чтобы гадать.
- **КОД — TODO/FIXME.** Только буквальные маркеры в комментариях — высокая
  точность, без словесного шума. Слова вроде «placeholder»/«черновой»/«ждёт»
  специально не грепаются широко: в этом проекте «placeholder» часто законный
  архитектурный термин (`RS_LevelGraph.PLACEHOLDER_ROOM_SCENE`,
  `RS_RoomPresetLibrary` про заглушку до появления библиотеки пресетов), а не
  флаг недоделки — широкий grep по такому даёт больше шума, чем сигнала.
  Настоящую «черновую» пометку видно по контексту при чтении, не по регулярке.
- **ДОКУМЕНТАЦИЯ — известные пробелы.** Раздел «## …Известные пробелы» в
  `Состояние проекта.md`, вытянутый как есть — это уже отсортированный
  человеком список, не пересчитывать заново. Полезно сверить с TODO из
  предыдущей секции: если пробел в вики описан, а TODO в коде на ту же тему
  нет (или наоборот) — стоит заметить расхождение, а не тихо пройти мимо.
- **СВЕРКА DOCS-SYNC.** Отсюда и вызывается навык `docs-sync` — его же
  скрипт `check_doc_references.py`, без дублирования логики. Если он
  находит что-то новое (не из уже известного фонового шума — «GECS и правила
  движка.md» про example_card_game, `S_EnemyAI` из «Известных пробелов») —
  это и есть хвост уровня документации, им должен заняться `docs-sync`, не
  этот скилл.

## Что делать с результатом

Не чинить ничего в рамках этого скилла. Роль — назвать три вещи пользователю
одним связным текстом, а не пятью необработанными логами:
1. что реально в работе (git + колонка «В работе», и явно сказать, если они
   расходятся);
2. что ближайшее по плану (верх «К выполнению», в порядке карточек на доске —
   порядок канбана в этом проекте уже приоритетный, «делать первым» помечено
   в самих карточках, не выдумывать свой);
3. какие хвосты обнаружились (стэши, TODO без карточки, пробел из вики без
   соответствующей задачи в бэклоге/доске, находки docs-sync) — и по каждому
   спросить или предложить конкретное действие (завести карточку, взять в
   работу, оставить как есть), а не просто перечислить и остановиться.

Если пользователь после среза просит взяться за что-то из хвостов или из
доски — это уже отдельная задача, не продолжение этого скилла.

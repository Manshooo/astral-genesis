# Godot Pipeline

**Версия 1.4.0.** Blender 4.2+ (разрабатывается и проверяется на 5.2 LTS), Godot 4.7.

Аддон Blender для поставки ассетов в Godot 4: **одна коллекция → один `.glb` →
одна независимая единица импорта**, со своим `.import`-файлом, настройками
коллизий и материалами, которыми владеет Godot.

Аддон состоит из **двух половин**, и это не деталь реализации, а то, что нужно
держать в голове с первого дня: панель в Blender пишет намерение в custom
properties, а превращает его в настоящие узлы физики скрипт
`godot/collision_post_import.gd` уже на стороне движка. Без второй половины
метаданные коллизий не делают ровно ничего — см. [Обязательный
шаг](#обязательный-шаг-скрипт-на-стороне-godot).

---

## Установка

Исходник аддона лежит **в репозитории игры** (`tools/blender/godot_pipeline/`),
а Blender грузит расширения из своей папки:

```
%APPDATA%\Blender Foundation\Blender\<версия>\extensions\user_default\godot_pipeline
```

Пока это два разных каталога, они расходятся молча. Поэтому установка по
умолчанию делает **связь, а не копию**:

```powershell
pwsh tools/blender/install.ps1
```

Папка расширений становится тем же каталогом, что и в репозитории: правка видна
Blender сразу, `git diff` показывает то, что реально загружено, и вопрос «в
какой копии я только что правил» перестаёт существовать. Junction на каталог не
требует прав администратора; если связать не вышло, скрипт кладёт копию и
честно об этом говорит.

Проверить: Preferences → Get Extensions → Godot Pipeline, версия **1.4.0**.
Blender подхватывает изменённый Python только при перезагрузке аддона или
перезапуске — связь избавляет от копирования, но не от этого.

Про `-Pull`, бэкапы и почему аддон живёт в `tools/`, а не в `dev/` — в
[`tools/blender/README.md`](../README.md).

**Без репозитория** (поставить на чужую машину) есть два пути:

```bash
blender --command extension build --output-dir ..
```

даёт `godot_pipeline-1.4.0.zip` для Preferences → Get Extensions → ▾ → *Install
from Disk…*. Либо положить папку в `<blender config>/scripts/addons/` как
обычный legacy-аддон — `bl_info` в `__init__.py` оставлен ровно для сборок, где
расширений нет.

## Быстрый старт

1. Preferences → Add-ons → Godot Pipeline → указать **Godot Project** (папку с
   `project.godot`). Кнопка *Detect Godot Project* найдёт её сама, если `.blend`
   лежит внутри репозитория игры.
2. В 3D-вьюпорте: `N` → вкладка **Godot**.
3. Collisions → Godot Side → **Install Godot Import Script**. Один раз на
   проект; без него коллизии не построятся.
4. Выбрать коллекцию → *Mark as Godot Asset* → выбрать профиль.
5. Указать папку назначения (относительно корня проекта Godot).
6. **Export All Assets**.

Профили лежат в настройках аддона, но кнопка *Save to Project* пишет их в
`<godot>/godot_pipeline.json` — файл кладётся в репозиторий, и все `.blend`
проекта используют одни и те же настройки. Обратно — *Load from Project*.

### Где что в интерфейсе

| Место | Что там |
|---|---|
| 3D-вьюпорт → `N` → **Godot** | экспорт, валидация, ренейминг текстур, активный ассет, выделенные объекты, отчёт |
| … → **Collisions** | тела, формы, слои, превью, подпанель **Godot Side** |
| Properties → Collection → **Godot** | настройки ассета: профиль, папка, имя файла |
| Properties → Object → **Godot** | суффикс-подсказка и имя при экспорте |
| Properties → Material → **Godot** | `-alpha`, `-vcol`, путь к внешнему `.tres` |
| Preferences → Add-ons → Godot Pipeline | корень проекта, библиотека профилей, Dry Run, Verbose Log |

## Почему текстуры возвращаются в корень

Это не баг экспорта, а поведение импортёра Godot по умолчанию — и именно из
него растут два главных решения аддона.

У сцены glTF есть опция импорта `gltf/embedded_image_handling`, и её значение по
умолчанию — **`Extract Textures` (1)**. При каждом импорте Godot достаёт
встроенные в `.glb` картинки и пишет их файлами **рядом с самим `.glb`** под
именем `<имя_glb>_<имя_картинки>.png`
(`modules/gltf/gltf_document.cpp`, `_parse_image_save_image`).

Перезапись пропускается только если файл уже лежит по этому пути и его md5
совпадает. Текстуры **перенесли** — значит по исходному пути их нет, значит при
следующем реимпорте Godot создаёт их заново. Плюс `.glb` лежит в корне проекта,
поэтому и мусор оказывается в корне.

Отсюда:

1. **Один ассет — своя папка.** Даже при извлечении текстур мусор остаётся
   локальным и не смешивается с чужим.
2. **Если материалы настраиваются в Godot (color + normal + ORM), картинок в
   `.glb` быть вообще не должно.** Аддон экспортирует материалы *со слотами и
   именами, но без изображений* (`export_image_format='NONE'`) и ставит
   `gltf/embedded_image_handling=0` (`Discard All Textures`). Извлекать нечего —
   ничего и не появится.

Связь «материал в glTF → внешний `.tres`» аддон пишет прямо в `.import`:

```ini
_subresources={
"materials":{
"MAT_prop_complex_door":{
"use_external/enabled":true,
"use_external/path":"res://assets/props/materials/MAT_prop_complex_door.tres"
}
}
}
```

Godot не перезаписывает материал, на который есть такая ссылка, так что ORM
переживает любое количество правок геометрии в Blender. Единственное, что рвёт
связь, — **переименование материала в Blender**: ключ здесь это имя.

Оговорка про `Extract Once` (`materials/extract=1`): это **разовый bootstrap**,
а не механизм долговременного владения. Если `.tres` по целевому пути уже
существует, а ссылки в `_subresources` нет, Godot умеет записать
`use_external/enabled:true` с **пустым** путём и сбросить `extract` в `0` —
материал при этом молча отвязывается. Долговременная гарантия ровно одна:
явная ссылка с настоящим путём, и её аддон пишет сам.

## Политики материалов

| Политика | Что в `.glb` | `gltf/embedded_image_handling` | Когда |
|---|---|---|---|
| **Godot owns materials** (по умолчанию) | слоты и имена, без картинок | `0` Discard | материалы настраиваются в Godot: color + normal + ORM |
| **Extract textures** | картинки внутри | `1` Extract | быстрый прототип; безопасно только с «папка на ассет» |
| **Keep embedded** | картинки внутри | `3` Uncompressed | мелочь, где не жалко VRAM |

Сопутствующие настройки профиля:

* **Generate Missing `.tres`** (вкл) — создать пустой `StandardMaterial3D` для
  материала, у которого файла ещё нет, чтобы ссылке было куда указывать.
* **Link External Materials** (вкл) — собственно запись `use_external` в
  `.import`.
* **Material Folder** / **Texture Folder** — общие папки (`assets/materials`,
  `assets/textures`). Пустая Material Folder означает «рядом с ассетом».
* **Copy Textures** (выкл) — скопировать картинки из Blender в проект, с
  проверкой по содержимому: повторный экспорт неизменного ассета не трогает ни
  один файл и не провоцирует реимпорт.

### Общий материал или личный

Properties → Material → Godot → **Lives**:

| Значение | `.tres` | текстуры |
|---|---|---|
| **Shared folder** (по умолчанию) | Material Folder профиля | Texture Folder профиля |
| **Beside the asset** | `<ассет>/materials/` | `<ассет>/textures/` |

Правило простое: у палитрового материала десятки потребителей, поэтому адрес у
него обязан быть один — общий. У материала с личным набором карт потребитель
ровно один, и «удалить ассет» должно быть одним движением, а не охотой по общим
папкам.

Текстуры всегда едут за своим материалом — иначе уникальная карта легла бы в
общую кучу и потеряла владельца. **Override Path** перебивает и то и другое,
если нужен точный `res://`-путь.

### Что уезжает в проект, а что остаётся в .blend

Слоёвый пейнтер запекает **каждый включённый канал**: AO, roughness, metallic,
displacement. Это не мусор — из них его же custom bake target собирает
упакованный ORM, — но в игре нужен только результат. Поэтому Copy Textures
отбрасывает всё, что по суффиксу опознаётся как промежуточное, и оставляет
четыре карты конвенции: `_albedo`, `_orm`, `_n`, `_emission`.

Незнакомый суффикс **копируется**, а не выбрасывается: ошибиться в сторону
лишнего файла дешевле, чем потерять карту. И то и другое попадает в отчёт —
молча здесь не происходит ничего.

Отсюда порядок: сначала **Rename Textures**, потом экспорт. У картинки с именем
от Ucupaint (`MAT_door Roughness`) суффикса нет, и она уедет как незнакомая.

## Куда всё это пишется

Папка назначения — свойство **профиля** (`dest_dir`), плюс `subfolder_per_asset`
и переопределение на самой коллекции. Значения по умолчанию —
`assets/characters`, `assets/levels`, `assets/props`, `assets/props/interactive`
— это стартовая точка аддона, а не раскладка конкретной игры.

**Для astral-genesis авторитет — §1 «Организация файлов»** в
[Blender-Godot пайплайн](../../../docs/astral-genesis/Справка/Blender-Godot%20пайплайн.md):
категория (`rooms`, `props`, `monsters`) — это один `.blend`, один `.glb` и
свои `materials/`, `textures/`, `models/` рядом. Профили под проект правятся
один раз и кладутся в `godot_pipeline.json`.

Про материалы стоит помнить главное: **имя материала в Blender — это ключ**.
Один `MAT_room_base` в трёх `.blend` ссылается на один и тот же `.tres`. Меш с
двумя материалами в разных слотах даёт два surface в Godot, и каждый
привязывается по своему имени — отдельного кода это не требует.

## Профили

| Профиль | Для чего | Ключевые отличия |
|---|---|---|
| **Character** | монстры, NPC | анимации ON (по действиям), только деформирующие кости, rest pose, модификаторы НЕ применяются (шейпкеи живы), LOD/shadow mesh выключены |
| **Level Chunk** | комнаты, коридоры | модификаторы применяются, LOD + shadow meshes, `Light Baking = Static Lightmaps` |
| **Prop** | мебель, декор | модификаторы применяются, LOD + shadow meshes, `Light Baking = Dynamic` |
| **Interactive** | дверь, рычаги, сундуки | корень импортируется как `StaticBody3D`, анимации ON, custom properties едут как glTF extras |

Профили редактируются и добавляются в настройках аддона. Значения — стартовая
точка, ценность в том, что все ассеты одного типа экспортируются одинаково.

Оговорка про `Root Node` у **Interactive**: `nodes/root_type="StaticBody3D"`
делает телом **корень сцены**, и это тело остаётся без формы, если коллизия
живёт на детях. Само по себе безвредно, но и бесполезно — ставить его стоит
только когда форма действительно вешается на корень. Для двери, у которой
коллизия приходит из `.glb` детьми, `Node3D` честнее.

## Collection per Object — пакетная нарезка на ассеты

Сайдбар → **Godot** → *Selected Objects* → **Collection per Object**.

Каждому выделенному объекту создаётся своя коллекция, названная по объекту, объект
из текущей коллекции отвязывается, новая коллекция вкладывается **внутрь той, из
которой объект забрали**. Имена объектов не меняются.

Ключевое: из имени коллекции вырезаются суффиксы Godot. Поэтому

```
Furniture/                    Furniture/
  Chair                         Chair/
  Chair-col          →            Chair
  Table                           Chair-col
  Table-colonly                 Table/
                                  Table
                                  Table-colonly
```

меш и его коллизия оказываются **в одной коллекции**, то есть в одном ассете —
ровно то, что дальше уедет одним `.glb`.

Опции (F9 или диалог при вызове):

| Опция | По умолчанию | Что делает |
|---|---|---|
| Strip Godot Suffixes | вкл | вырезать `-col`, `-colonly`, `-navmesh` и остальные из имени коллекции |
| Keep `.001` Suffix | вкл | выключить — и `Barrel`, `Barrel.001`, `Barrel.002` сольются в одну коллекцию `Barrel` |
| Reuse Existing | вкл | если у родителя уже есть коллекция с таким именем — класть туда, а не плодить `Vase.001` |
| Take Child Objects | выкл | тащить за объектом его непроцессированных детей по иерархии парентинга |
| Mark as Godot Asset | выкл | сразу пометить новые коллекции на экспорт и назначить профиль |

Повторный запуск — no-op: объект, уже лежащий в коллекции с целевым именем,
пропускается.

## Коллизии без мусора в именах

Вкладка **Godot → Collisions**. Тип тела и форма хранятся в custom properties,
имена объектов не трогаются вообще.

### Обязательный шаг: скрипт на стороне Godot

Custom properties доезжают до Godot как `node.get_meta("extras")` и **сами по
себе не создают ничего**. Суффиксы обрабатывает встроенный импортёр, метаданные —
нет. Поэтому в комплекте идёт `godot/collision_post_import.gd`
(`EditorScenePostImport`), который читает метаданные и строит настоящие узлы.

**Collisions → Godot Side → Install Godot Import Script** копирует его в
`res://addons/godot_pipeline/collision_post_import.gd` и прописывает в
`import_script/path` всех профилей. Без этого валидатор выдаёт предупреждение, а
в Godot ничего не появится.

Скрипт — **копия**, а не связь: он должен лежать внутри проекта Godot, иначе
`res://`-путь не разрешится. После правки `godot/collision_post_import.gd`
в аддоне кнопку надо нажать заново.

### Что доступно

| Body | Collision |
|---|---|
| None | None |
| StaticBody3D | Box |
| AnimatableBody3D — двери, платформы, лифты | Sphere |
| RigidBody3D (+ Mass) | Capsule — стоит вдоль Blender Z = Godot Y |
| CharacterBody3D | Cylinder — так же |
| Area3D — триггеры, подборы | Simple (Convex) |
| VehicleBody3D | Trimesh (Concave) — только на статике |
| PhysicalBone3D — кость рэгдолла (+ Mass) | |

Плюс **Collision Margin**, **Collision Layer/Mask**, **Collision Priority** и
**Keep Mesh** (оставить визуальный меш там, где по умолчанию он бы исчез).

### Слои по именам, а не по счёту клеток

**Имена слоёв читаются из `project.godot`.** Секция `[layer_names]` разбирается
на лету (файл перечитывается по mtime, обновлять руками нечего), и вместо
безымянной сетки из 32 квадратиков во вкладке появляются подписанные
переключатели: `static_colliders`, `interactives`, и так далее. Слой,
переименованный в Godot, переименовывается и здесь — а не начинает молча
означать что-то другое. Полная сетка на 32 бита остаётся рядом, чтобы
безымянный слой тоже был достижим; дырки в нумерации подписываются как
«Layer N». Если имён в проекте нет, вкладка работает как раньше и говорит об
этом.

### PhysicalBone3D — кости рэгдолла

Это единственное тело, которое **не встаёт на место объекта**: оно уезжает под
`Skeleton3D → PhysicalBoneSimulator3D` (раскладка Godot 4.4+), а форма
становится его ребёнком. Тегируется при этом болванка-прокси, поэтому её меш
удаляется, в отличие от `StaticBody3D`, где узел и есть визуал.

Кость берётся **из привязки**: `Ctrl+P → Bone` в Blender, дальше glTF несёт
это сам, Godot делает `BoneAttachment3D`, а скрипт постимпорта читает имя
оттуда. Печатать ничего не нужно, и форма двигается вместе с костью при
позировании. Поле **Bone** во вкладке — переопределение для случаев, которые
привязкой не выражаются.

Рядом — **Joint**: None / Pin / Cone Twist / Hinge / Slider / 6DOF. По умолчанию
Cone Twist, обычный выбор для конечностей и шеи; None означает, что кость
симулируется свободно от родителя, и валидатор про это скажет.

Ловушка, которую ловит валидатор: при **Export Deformation Bones Only**
контрольная кость до `.glb` не доезжает, так что `PhysicalBone3D` назвал бы
кость, которой в скелете Godot нет — а симптом был бы один, тело просто не
появляется.

Мелочь, на которую можно потратить час: `PhysicalBone3D.get_bone_id()` возвращает
`-1` до тех пор, пока не вызван `physical_bones_start_simulation()`, и ещё кадр
после него. Связь идёт по `bone_name`; id — производное, которое симулятор
заполняет лениво. Проверять надо `skeleton.find_bone(bone.bone_name)`.

Про margin честно: `Shape3D.margin` **игнорируется GodotPhysics3D** и работает
только в Jolt. Jolt — движок по умолчанию для проектов, созданных начиная с
Godot 4.6, так что в 4.7-проекте astral-genesis он действует; в старом проекте
на GodotPhysics3D значение просто ничего не изменит.

### Как это устроено

Форма — это отдельный объект-прокси, **ребёнок** нужного объекта:

```
Chair          body = StaticBody3D,  shape = None
  CO_Chair_Box body = None,          shape = Box
```

после импорта в Godot:

```
Chair (StaticBody3D)
  Chair_mesh (MeshInstance3D)
  CO_Chair_Box (CollisionShape3D → BoxShape3D)
```

Тело **заменяет** узел и забирает его трансформ, меш уходит вниз — ровно так же
поступает штатный импортёр для `-rigid`. Прокси-меши в Godot удаляются, остаётся
только форма.

Геометрия прокси строится сразу нужного размера, а не масштабированием единичного
куба, поэтому у прокси всегда scale 1 — Godot не ругается на неравномерный
масштаб на узлах коллизий. Размеры примитивов движок берёт из AABB меша,
домножая на масштаб узла, так что ось-конвертация Z-up → Y-up не участвует в
арифметике вообще и не может разъехаться.

Имя прокси — `CO_<объект>_<форма>`. Префикс не случайный: `Chair_col` штатный
импортёр прочитал бы как суффикс коллизии и построил бы вторую, трисетчатую.

### Кнопки

* **Add Collision** — задать body выделенным объектам и построить форму по их
  габаритам. `Shape From: This Object` — взять сам меш (для Convex/Trimesh).
* **Refit Shapes** — перестроить формы под изменившуюся геометрию.
* **Copy to Selected** — раскатать настройку активного объекта на остальные
  выделенные, каждому подгоняя форму под его собственные габариты.
* **Select Proxies** — выделить все прокси в сцене.
* **Clear Collision** — удалить прокси и очистить свойства.
* **Preview: Wire / Solid / Bounds / Hidden** — Wire рисует каркас поверх меша и
  читается в любом режиме затенения; Solid красит голубым и переключает вьюпорт
  на Object color; Bounds — самый дешёвый вариант для тяжёлой сцены. Для
  полупрозрачности поверх Solid включи X-Ray (Alt+Z). Прокси всегда
  `hide_render`.

### Что ловит валидатор

* Trimesh на подвижном теле — `ConcavePolygonShape3D` работает только на статике
  (блокирующая ошибка, оператор тоже откажется её создавать);
* метаданные есть, а в профиле выключены Custom Properties — данные молча
  потерялись бы при экспорте (блокирующая ошибка);
* метаданные есть, а import script не назначен — в Godot ничего не построится;
* неравномерный масштаб на объекте с телом — Godot об этом предупреждает;
* круглая форма (Sphere/Capsule/Cylinder) под неравномерным масштабом — Godot
  выберет один радиус, и форма перестанет совпадать с тем, что нарисовано;
* форма без тела выше по иерархии — скрипт подставит `StaticBody3D`;
* на объекте одновременно суффикс-подсказка и метаданные — коллизия построится
  дважды;
* Trimesh из более чем 5000 полигонов;
* `PhysicalBone3D` без кости — ни привязки, ни поля;
* `PhysicalBone3D` на объекте, не привязанном ни к какой арматуре: в `.glb` не
  будет скелета;
* кость, которой в арматуре нет;
* **кость не деформирующая при Export Deformation Bones Only** — она не доедет
  до Godot, и тело просто не появится, без единого сообщения;
* `Joint = None` на кости рэгдолла — она будет симулироваться отдельно от
  остального скелета (это INFO, иногда так и надо).

## Ренейминг текстур из Ucupaint

Кнопка **Rename Textures** в панели Godot. Ucupaint называет запечённое по
каналу — «MAT_door Color», «MAT_door Ambient Occlusion», — а конвенция проекта
ждёт `T_<база>_<карта>`:

| Из Ucupaint | Станет |
|---|---|
| `MAT_door Color`, `Base Color`, `Albedo`, `Diffuse` | `T_door_albedo` |
| `MAT_door Normal`, `Bump` | `T_door_n` |
| `MAT_door_ORM`, `Occlusion Roughness Metallic`, `AO Roughness Metallic` | `T_door_orm` |
| `MAT_door Emission`, `Emissive` | `T_door_emission` |
| `Ambient Occlusion` / `Roughness` / `Metallic`, `Metalness` | `_ao` / `_roughness` / `_metallic` |
| `Displacement`, `Height` / `Opacity`, `Alpha` / `Specular` | `_height` / `_alpha` / `_specular` |

Первые четыре — то, что по §6 пайплайна и должно существовать; остальные
переименовываются тоже, но подсвечиваются красным: отдельный `_roughness`
означает, что упаковка в ORM не состоялась.

Godot имён текстур не разбирает вообще — это целиком конвенция проекта, и
именно поэтому её надо кем-то поддерживать: имена с пробелами и с префиксом
материала иначе доезжают до коммита.

**Переименовывается и файл на диске**, с обновлением `filepath` датаблока —
иначе в Godot уехало бы старое имя, потому что экспортёр копирует файлы по
имени. Относительный путь (`//`) остаётся относительным. Ничего не
перезаписывается: если имя занято, файл пропускается с сообщением.

Диалог показывает список до применения — это не операция «нажми и надейся».
Область: *Selected* или *All*. Повторный прогон ничего не делает.

Чего плагин намеренно не знает: **`ARM`** как синоним ORM. В проекте с
риггингом `_arm` — это почти всегда часть тела, и `Shield_arm → T_Shield_orm`
хуже, чем набрать имя ORM руками. Разделитель обязателен и в остальных случаях:
`Armor` не читается как `arm`, `Colorful` — не как `color`.

## Подсказки Godot по именам

Аддон **не переименовывает объекты в `.blend`**. Тип узла хранится свойством, а
суффикс подставляется только на время экспорта и снимается сразу после. В
`.blend` остаётся `Walls`, в `.glb` уезжает `Walls-col`.

Object Properties → Godot, или *Apply to Selected* в сайдбаре:

| Значение | Суффикс | Что получится в Godot |
|---|---|---|
| None | — | обычный `MeshInstance3D` |
| `-col` | `-col` | меш + `StaticBody3D` с `ConcavePolygonShape3D` |
| `-convcol` | `-convcol` | меш + `StaticBody3D` с `ConvexPolygonShape3D` |
| `-colonly` | `-colonly` | только коллизия, визуальный меш выбрасывается |
| `-convcolonly` | `-convcolonly` | только выпуклая коллизия |
| `-rigid` | `-rigid` | `RigidBody3D` |
| `-vehicle` / `-wheel` | | `VehicleBody3D` / `VehicleWheel3D` |
| `-navmesh` | `-navmesh` | навигационная сетка |
| `-occ` / `-occonly` | | `OccluderInstance3D` |
| `-noimp` | `-noimp` | узел удаляется при импорте (блокаут, референсы, хелперы) |

Material Properties → Godot: `-alpha` (принудительная прозрачность) и `-vcol`
(вертексные цвета). Там же, в Object → Godot, у объекта с действием появляется
`Loop in Godot` — он добавляет `-loop` к имени анимации при экспорте.

**Как Godot на самом деле читает суффиксы** (`_teststr`/`_fixstr` в
`editor/import/3d/resource_importer_scene.cpp`, в документации этого нет):

* три формы, все регистронезависимые: `Wall-col`, `Wall_col` и `Wall$col` —
  причём `$`-форма ищется **в любом месте** имени, а не только в конце;
* перед сравнением с конца отбрасывается хвост из цифр, пробелов и `_`, поэтому
  `Wall-col_001` тоже считается коллизией;
* специфичное имеет приоритет: `-convcolonly` не читается как `-col`,
  `-occonly` не как `-occ`;
* `Protocol`, `Column`, `Wheelbarrow` не трогаются — нужен разделитель.

Ровно эти правила реализованы в вырезании суффиксов и в валидаторе, так что
`Rock_col` ловится наравне с `Rock-col`.

Custom properties объекта уезжают в glTF `extras`, и Godot кладёт их в метаданные
узла — читаются как `node.get_meta("extras")`. Удобно для интерактивных объектов:
тип взаимодействия, id, параметры — прямо из Blender.

## Валидация

Кнопка **Validate Assets** (и автоматически перед каждым экспортом) ловит то, что
иначе всплывает уже в движке:

* точка и другие символы из `.:@/"%` в имени — Godot их вырезает из имён узлов;
* два объекта, которые схлопываются в один узел после добавления суффикса;
* вручную дописанный суффикс поверх свойства — они бы сложились;
* материал без UV-развёртки, пустой слот материала, больше двух UV-каналов
  (Godot использует максимум UV и UV2);
* материал вида `Stone.001` — случайный дубль, который сломает связь с `.tres`;
* шейпкеи под профилем с *Apply Modifiers* (блокирующая ошибка: они пропадут);
* отрицательный масштаб (вывернутые нормали);
* несколько арматур в одном ассете, неприменённый масштаб арматуры;
* два ассета, пишущих в один файл; ассет без профиля или с несуществующим
  профилем; пустая коллекция;
* `Extract textures` без «папки на ассет» — картинки лягут поверх соседей;
* `.blend`, ни разу не сохранённый: относительные пути посчитаются не оттуда;
* объект с тем же именем, что у его `.glb`: Godot допишет корню сцены цифру
  (godotengine/godot#112405), и `NodePath` в сценах начнут указывать мимо;
* данные меша с чужим именем (`Cube.011`): glTF берёт имя меша из данных, а не из
  объекта (INFO; общие данные инстансов не отмечаются);
* **контракт клетки кита**, если у профиля задан *Cell Size*/*Height Limit*: см.
  [Кит тайлов](#кит-тайлов);
* всё, что перечислено в разделе про коллизии.

Ошибки (`ERROR`) блокируют экспорт, предупреждения — нет. Результат остаётся в
подпанели **Report** до следующего прогона.

## Работа с `.import`

По умолчанию аддон **правит только существующие** `.import`, меняя те ключи,
которыми владеет, и не трогая ничего больше: `uid`, `path`, `dest_files`,
`lightmap_texel_size` и любые ручные правки остаются как были. Если
`_subresources` отредактирован вручную во что-то, что не парсится, аддон
сообщает об этом и не трогает блок.

Ключи, которыми владеет аддон:

```
nodes/root_type, nodes/apply_root_scale, nodes/root_scale
nodes/use_name_suffixes, nodes/use_node_type_suffixes
meshes/ensure_tangents, meshes/generate_lods, meshes/create_shadow_meshes
meshes/light_baking
animation/import, animation/fps
gltf/embedded_image_handling
import_script/path
_subresources → materials/<имя>/use_external
```

Если `.import` ещё нет (файл только что экспортирован, Godot его не видел),
аддон по умолчанию сообщает об этом и пропускает. Включи *Create .import If
Missing* в профиле, чтобы он писал минимальный корректный `.import` сразу —
`importer="scene"`, `importer_version=1`, `type="PackedScene"` плюс `[params]`;
`uid` и кэш Godot проставит сам при первом сканировании.

Порядок при первом заведении ассета:

1. экспорт;
2. открыть Godot один раз (он создаст `.import` и `uid`);
3. экспорт ещё раз — аддон допишет свои ключи.

Либо просто включить *Create .import If Missing* и пропустить шаг 2.

## Пакетный экспорт из командной строки

```bash
blender --background monsters.blend --python-expr "import godot_pipeline, sys; sys.exit(godot_pipeline.export_all_headless())"
```

Только проверка, без записи:

```bash
blender --background buildings.blend --python-expr "import godot_pipeline, sys; sys.exit(godot_pipeline.validate_headless())"
```

Обе функции возвращают количество ошибок — годится как код возврата шага CI.
Обе принимают необязательный `project_root`: на раннере, где настроек Blender
нет, корень проекта задаётся аргументом, а не Preferences.

Аддон при этом должен быть **включён** в тех настройках, которые наследует
фоновый запуск. Под `--factory-startup` он не подхватывается — так тесты и
делают: копируют плагин во временную папку скриптов и указывают на неё
`BLENDER_USER_SCRIPTS`.

Отбора «только изменённые» здесь нет, и это осознанно: сравнивать `.glb` с
временем правки `.blend` бессмысленно — любое сохранение файла делает его новее
всех своих ассетов сразу, так что фильтр либо пропускал бы всё, либо ничего.
Гранулярность «этот ассет не менялся» из mtime одного `.blend` не выводится.

  он попадал в файл, экспорт заводил ему `.tres` и ссылки, а «Extract Once» в
  Godot создавал `.tres` заново на каждом холодном импорте.
* **Ренеймер берёт базу имени после токена `MAT_`**, где бы тот ни стоял.

* **Кит тайлов** — два поля профиля и проверка контракта клетки.
* **Валидатор** ловит объект с именем своего `.glb` и данные меша с чужим именем.

## Кит тайлов

Профиль → **Tile Kit**: *Cell Size* и *Height Limit*. Ноль — не кит, проверка
молчит. Числа — данные проекта, а не аддона, поэтому живут в профиле и едут в
`godot_pipeline.json`.

Генератор ставит тайл в клетку трансформом и поворачивает на четверти оборота,
ничего не подгоняя. Выступ за грань клетки даже на сантиметры при повороте
переезжает на другую сторону и складывается с погрешностью соседа — это видимый
шов. Поэтому габарит сверяется **по вершинам вычисленного меша** (после
модификаторов, в том числе сборщика), с допуском в миллиметр, от той же точки,
что станет началом координат `.glb`: при *Export at Origin* экспортёр glTF берёт
среднее положение корневых объектов коллекции, а не центр габарита.

Не участвуют прокси коллизий (они скрыты от рендера и становятся формами) и
объекты «не импортировать». Чего проверка **не** знает: где должен стоять проём.
Рамка, сдвинутая на 3 см внутри клетки, ей не видна — это задача проверки по
сценам в Godot.

## Что аддон намеренно не делает

* **Не разбирает вложенные ассеты.** Если коллекция инстансится внутри другой,
  геометрия уедет в оба `.glb`. Blender Studio решала это своим кодом,
  подменяющим инстансы на ссылку по id и восстанавливающим иерархию плагином на
  стороне Godot. Для процедурного подземелья, где комнаты собираются кодом, это
  не нужно; понадобится — это следующий слой поверх текущего.
* **Не генерирует `.tscn`.** Импортированный `.glb` инстансится в свою сцену
  вручную — там же вешаются скрипты и игровая логика, и эта сцена переживает
  любой реимпорт (§9 пайплайна).
* **Не пишет `uid` в `.import`.** Их владелец — Godot.
* **Не запекает материалы.** ORM собирается либо в Ucupaint через custom bake
  target, либо в Godot из трёх карт.
* **Не подменяет материалы в рантайме.** Привязка живёт в `.import`, то есть
  только на импорте в редакторе. Если когда-нибудь понадобится грузить `.glb` на
  лету, механизмом станет `GLTFDocumentExtension` — см. §8 пайплайна.
